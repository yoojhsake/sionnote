> 근거 표기: **조회** = 이 테넌트 화면·PowerShell·Graph에서 직접 읽은 값 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못함(시도 방법·사유·다음 방법 병기). 계정·테넌트 식별자는 게시하지 않았다.

| 항목 | 내용 |
|---|---|
| 증상 | 화면에서 "빈 칸"이던 값을 스크립트로 계산하자 예외가 나거나 집계에서 누락됨. 별도로 결과 표의 이름 열이 서로 섞임 |
| 먼저 볼 것 | 대상 값이 null인가 / 한 열이 두 가지 개체를 가리키는가 |
| 원인 | null을 "0"이나 "오래됨"처럼 다루는 스크립트 가정, 같은 `DisplayName`을 두 곳에 사용 |
| 대처 | 계산 전에 null을 검사해 "해당 없음"으로 출력, 열을 `App`과 `CredentialName`으로 분리 |

## 전체 기록

### 1. 증상

- 화면에서는 "빈 칸"이던 값을 스크립트로 계산(경과 시간 등)하자 예외가 났습니다. 대표적으로 날짜 값이 null인데 뺄셈을 한 경우입니다(조회). 예외 문구는 `Cannot convert null to type "System.DateTime"` 형태였습니다.
- 앱 등록의 자격증명 만료를 모아 표로 만들 때, 같은 `DisplayName`을 앱 이름과 자격증명 이름 두 곳에 썼더니 **어느 이름인지 구분되지 않았습니다**(조회).

### 2. 먼저 확인할 것

- 실패한 항목의 대상 값이 **null(값 없음)**인지 봅니다. 화면에서 빈 칸이면 스크립트에서는 null일 가능성이 큽니다.
- 결과 표를 만들 때는 **한 열이 한 가지 개체만 가리키는지** 봅니다.

### 3. 시도와 결과

**3-1. null이 만든 문제 세 가지**

| 상황 | 문제 | 고친 것 |
|---|---|---|
| 온프레미스와 동기화한 적이 없는 테넌트의 "마지막 동기화 시각" | null에서 현재 시각을 빼는 계산이 예외 | null이면 계산하지 않고 **"동기화 미구성(해당 없음)"**으로 출력 |
| 정책의 "수정 시각"이 비어 있는 경우 | 수정 시각 기준 비교가 거짓이 되어 **누락** | 수정 시각이 없으면 **생성 시각**을 대신 사용 |
| 로그인 기록이 한 번도 없는 사용자 | "오래 로그인하지 않음"과 **섞여 집계** | null(기록 없음)을 따로 세어 구분 |

```powershell
# null 검사 예: 마지막 동기화 시각이 없으면 경과 시간을 계산하지 않는다
$last = $org.OnPremisesLastSyncDateTime
if ($null -eq $last) { '동기화 미구성(해당 없음)' }
else { [int]((Get-Date) - $last).TotalMinutes }
```

**3-2. 결과 표의 이름 열이 섞인 경우**

앱 등록의 자격증명 만료를 모은 표에서 앱 이름과 자격증명 이름이 모두 `DisplayName`이었습니다. 열을 `App`과 `CredentialName`으로 나눴습니다. 서비스 주체의 자격증명도 만료 대상이므로 따로 집계 대상에 넣었습니다(조회).

### 4. 대처와 원복

- 두 경우 모두 스크립트와 출력 형식만 고쳤고, 테넌트 설정은 바꾸지 않았습니다. 원복할 변경은 없습니다.
- 결과 표에서 **해당 없음 / 정상 / 확인 불가**를 서로 다른 값으로 적어, 나중에 읽는 사람이 "값이 없어서 계산하지 않은 것"과 "계산했더니 정상인 것"을 구분할 수 있게 했습니다.

### 5. 운영에서는 이렇게 판단한다

1. null은 "0"도 "오래됨"도 아닙니다. **"없음"이라는 별도 상태**로 출력합니다.
2. 계산 전에 null을 검사합니다. 비교 조건에서 null이 거짓을 만들어 항목이 빠지지 않는지도 봅니다.
3. 표를 만들기 전에 **한 열이 한 가지 개체만 가리키는지** 확인합니다. 사람이 나중에 읽을 표일수록 열 이름이 의미를 분명히 해야 합니다.
