수행일은 2026-10-22이고, 프로그램 일정상 D2(Identity 구조) 주제입니다. 사용자 유형과 인증 방식은 10/19에 조회해 두었습니다.

## 목표
- Member/Guest, 그룹 유형, 인증 방식(PHS·PTA·Federation)을 정리한다.
- 동적 그룹이 사용자 속성 변경에 반응하는지 직접 확인한다.

## 절차
1. Entra > 그룹에서 **DG-Practice-02**(동적 사용자)를 새로 만든다. 기존 DG-Practice-01은 건드리지 않는다.
2. 규칙을 `user.department -eq "Practice02"`로 지정한다.
3. 라이선스는 Entra가 아니라 **M365 관리 센터의 "라이선스 할당" 패널**에서 그룹을 골라 할당한다.
4. 시험 사용자의 부서를 비움 → Practice02로 바꾸고, 그룹에 들어오는지 본다.
5. 부서를 다시 비워 원복한다.

## 실제 값
![DG-Practice-02 동적 구성원 규칙 화면. 속성 department, 연산자 Equals, 값 Practice02]({{ "/assets/images/2026/10/d2-dynamic-rule.png" | relative_url }})
*그림 2. 동적 규칙 화면 (빨간 상자: 규칙과 규칙 구문, 계정 정보는 가림)*

| 항목 | 값 |
|---|---|
| 사용자 유형 | 20명 전원 Member, Guest 0 |
| 그룹 수 | 9개 → 10개 (Microsoft 365 8 + 보안 1 → 보안 2) |
| 인증 방식 | 도메인 1개, Managed(Federated 없음), 조직 동기화 없음 |
| 부서 변경 후 | 구성원 1명 자동 가입, 사용자의 그룹 구성원 자격 2 → 3 |
| 그룹 라이선스 | 할당 요청 접수("라이선스가 할당되고 있습니다") |

인증 방식은 클라우드 전용 테넌트라 직접 실습이 안 되어, 아래처럼 문서로 정리했다.

| 방식 | 한 줄 정리 |
|---|---|
| PHS | 암호 해시의 해시를 동기화, 로그인 검증은 클라우드 |
| PTA | 로그인 검증을 온-프레미스 에이전트에 맡김 |
| Federation | 로그인을 외부 ID 공급자에 위임, 운영 부담이 가장 큼 |

## 막힌 곳과 미확인
- Entra의 그룹 라이선스 탭은 안내 문구만 있고 할당은 M365 관리 센터에서 한다.
- 그룹 라이선스가 사용 좌석(20/25)에 반영된 결과는 **미확인**(재조회 전).
- 부서를 비운 뒤 그룹에서 빠지는지도 **미확인**.

## 다음

- 실습용 그룹 DG-Practice-02는 정리 목록에 올려 두었다(삭제는 하지 않음).
