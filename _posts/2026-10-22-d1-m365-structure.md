수행일은 2026-10-22(목)이고, M365 구조가 주제입니다. 이 글은 변경 실습을 포함하므로 **무엇을 얼마나 바꿨고 어떻게 되돌렸는지**까지 적었습니다.

> 근거 표기: **조회** = 이 테넌트 화면·PowerShell에서 직접 읽은 값 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못한 값(시도 방법·막힌 이유·다음 방법 병기). 테넌트 ID·도메인·계정·사용자 이름은 게시하지 않았고, 시험 사용자는 "시험 사용자 1"처럼 적었습니다.

## 요약

| 항목 | 결과 |
|---|---|
| 한 일 | 시험 사용자 1의 Microsoft Planner 서비스 플랜을 끄고(앱 87→86) 다시 켬(86→87) |
| 핵심 확인 | 플랜을 꺼도 SKU 사용 수는 20/25 그대로 |
| 막힌 곳 | 가이드의 "제품 상세 > 앱 탭"이 없음 / 원복한 뒤 다시 읽으면 Planner가 꺼져 있는 일이 있었음 |
| 원복 | Planner 켜짐, 앱 87, 사용 20/25 |

## 1. 목표

1. Tenant와 Subscription이 서로 다른 개념임을 값으로 확인한다.
2. 라이선스(SKU)는 서비스 플랜의 **묶음**이며, 사용자 단위로 플랜 하나만 켜고 끌 수 있음을 직접 해 본다.
3. 그렇게 해도 **라이선스 사용 수는 줄지 않는다**는 점을 숫자로 확인한다.

## 2. 먼저 알아야 할 개념

![라이선스 제품에서 서비스 플랜 묶음, 사용자 단위 켜기·끄기로 이어지는 구조]({{ "/assets/images/2026/10/d1-license-model.png" | relative_url }})
*그림 1. 라이선스 구조와 실습 결과*

| 개념 | 쉬운 설명 | 이 테넌트 값 |
|---|---|---|
| Tenant | 회사의 계정 묶음(신원 경계) | 도메인 1개, 사용자 20, 그룹 9(실습 전) |
| Subscription | Azure 요금·리소스 묶음. 구독은 정확히 하나의 테넌트를 신뢰함 | 구독 1개, 테넌트 소속 확인 |
| SKU | 라이선스 상품 한 종류 | DEVELOPERPACK_V2_E5 1종(구매 25) |
| 서비스 플랜 | SKU 안의 개별 기능(Teams, Planner 등) | 12개 이상 Success, 사용자 화면 앱 목록 87개 |
| 조직 수준 항목 | 사용자별로 못 끄는 항목 | Microsoft Search, eCDN 등은 체크박스가 회색 |

## 3. 절차 (GUI 우선, PowerShell은 읽기 검증)

### 3-1. 변경 전 조회

1. 관리 센터 > 청구 > 라이선스 > 구독 탭에서 제품 1개와 "20/25 할당"을 확인했습니다. 값은 [사전작업 글]({{ "/m365/prework/" | relative_url }})에 있습니다.
2. 제품 이름을 눌러 사용자 목록을 열고, 사용자 한 명을 체크한 뒤 "앱 및 서비스 관리" 패널로 서비스 켜짐/꺼짐을 읽었습니다. 저장하지 않고 닫았습니다. 가이드가 안내한 제품 상세의 "앱" 탭은 화면에 없어 이 경로로 대신했습니다(아래 "작업 중 막힌 곳").
3. 같은 값을 `subscribedSkus` Graph 조회로 맞췄습니다(서비스 플랜 12개 Success).

### 3-2. 변경 실습 (09:25)

1. 관리 센터 > 사용자 > 활성 사용자 > **시험 사용자 1** 선택
2. 라이선스 및 앱 탭 > 앱 목록 펼치기 (앱 87개 표시)
3. **Microsoft Planner** 체크 해제 > "변경 내용 저장" → "변경 내용이 저장되었습니다" 메시지
4. 다시 열어 해제 상태가 유지되는지, 앱 개수가 86개로 줄었는지 확인
5. 같은 화면에서 Planner를 다시 체크 > 저장 → 앱 87개로 복귀

![사용자 라이선스 앱 목록. Microsoft Planner 체크가 해제되어 있음]({{ "/assets/images/2026/10/d1-planner-off.png" | relative_url }})
*그림 2. Planner 체크 해제 상태 (빨간 상자, 사용자 이름은 가림). 선명하게 다시 캡처한 화면이며, 이 시점의 앱 개수는 86개였습니다.*

![저장 직후 화면. 변경 내용이 저장되었다는 메시지와 앱(87) 표시]({{ "/assets/images/2026/10/d1-planner-restored.png" | relative_url }})
*그림 3. Planner를 다시 체크하고 저장한 직후 ("변경 내용이 저장되었습니다", 앱 87개, 사용자 이름은 가림)*

원복한 뒤 시간을 두고 같은 사용자를 다시 읽으면 Planner가 꺼져 있는 일이 두 번 있었습니다(10/22 10:3x, 10/23). 그때마다 Planner를 켜고 저장해 87개로 되돌렸고, 감사 로그를 보며 원인을 좁혔습니다. 과정은 [트러블슈팅: Planner 체크가 해제돼 있음]({{ "/m365/troubleshooting/planner-unchecked-license-audit/" | relative_url }})에 있습니다.

### 3-3. 사용자 5명 생성은 하지 않았다

- 사용자 계정 생성은 이번 실습 범위에서 제외했습니다. 사전작업 때 마법사를 열고 아무것도 입력하지 않은 채 취소만 했습니다(취소 확인창 "입력한 모든 정보가 손실됩니다").
- 좌석이 5개뿐이라, 5명에게 직접 라이선스를 주면 25/25가 되어 그룹 라이선스 실습([Identity 구조 글]({{ "/m365/d2-identity-groups/" | relative_url }}))의 좌석이 없어집니다. "4명 할당 + 1명 비움"으로 진행하는 방안을 확인 사항으로 남겼습니다.

## 4. 전·후 비교

| 항목 | 변경 전 | Planner 끈 직후 | 원복 후 |
|---|---|---|---|
| 앱 개수(화면) | 87 | 86 | 87 |
| Microsoft Planner | 체크됨 | 해제됨 | 체크됨 |
| 저장 메시지 | - | "변경 내용이 저장되었습니다" | 저장됨 |
| 라이선스 사용 수(SKU) | 20 / 25 | 20 / 25 | 20 / 25 |
| 조직 수준 회색 항목 | 끌 수 없음 | 끌 수 없음 | 끌 수 없음 |

- **핵심 확인**: 서비스 플랜을 꺼도 **SKU 사용 수는 20으로 그대로**입니다. 라이선스는 사용자에게 "제품 하나"로 할당되고, 플랜을 끄는 것은 그 안의 기능 노출만 바꿉니다.

| 전 → 후 | 켜짐(87) → 꺼짐(86) → 켜짐(87) |
| 왜 | 서비스 플랜 단위 제어가 가능한지, 사용 수가 변하는지 확인 |
| 근거 | 관리 센터 앱 및 서비스 관리 화면, 문서 아래 URL |
| 검증 결과 | 저장 메시지, 앱 개수 변화, 재조회 시 상태 유지, SKU 사용 20 유지 |
| 원복 방법 | Planner 체크를 다시 켜고 저장(실행 완료) |

## 5. 작업 중 막힌 곳

| 상황 | 한 줄 대처 | 글 |
|---|---|---|
| 가이드의 "제품 상세 > 앱 탭"이 없다 | 사용자를 먼저 선택하고 "앱 및 서비스 관리" 또는 사용자 상세의 "라이선스 및 앱" 탭을 사용 | [가이드의 메뉴가 화면에 없음]({{ "/m365/troubleshooting/guide-menu-differs-from-portal/" | relative_url }}) |

| 검증 방법 | 결과 |
|---|---|
| 화면: 저장 메시지 | 확인 |
| 화면: 앱 개수 87→86→87 | 확인 |
| 화면: 재조회 시 체크 상태 유지 | 확인 |
| 읽기 조회: SKU 사용 수 | 20 유지 |
| 회색 항목 | "조직 수준에서 할당됩니다. 사용자 단위로 할당할 수 없습니다" 문구 확인 |

## 7. 운영에서는 이렇게 판단한다

- 사용자에게 Teams만, 또는 Planner만 막고 싶을 때 SKU를 바꾸지 않고 **플랜 단위로 제어**할 수 있습니다.
- 다만 사용자 단위 수작업은 사람이 늘수록 누락됩니다. 많은 사용자에게 같은 규칙을 적용하려면 그룹 라이선스에서 플랜을 선택하는 방식([Identity 구조 글]({{ "/m365/d2-identity-groups/" | relative_url }}))이 더 맞습니다.
- 플랜을 껐을 때 사용 수가 줄지 않으므로, **비용 절감 수단으로 오해하면 안 됩니다.**
- "원복했다"고 한 번 쓰고 끝내면 틀릴 수 있습니다. 원복 후에도 시간을 두고 다시 읽어 확인해야 합니다.

## 9. 정리·남은 일

- 원복 완료(Planner 켜짐, 앱 87, 사용 20/25).
- 사용자 5명 생성은 아직 하지 않았습니다.

> PowerShell 원문은 복구하지 못해, 같은 출력 줄이 나오는 형태로 정리했습니다. 화면 확인 값은 실제와 같습니다.
