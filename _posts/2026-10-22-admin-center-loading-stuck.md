M365 Apps 관리 센터를 두 번 열었는데 두 번 모두 로딩에서 멈췄고, 다시 열자 앱 인벤토리에는 "프로비전 중, 최대 24시간" 안내만 남았습니다. 설정을 바꾸지 않고 기다렸다 다시 열어도 같은 안내 그대로여서, 목록 값은 측정 불가로 기록했습니다.

## 요약

- 화면이 멈추거나 안내만 나오면 값이 아니라 도구 상태를 읽은 것임
- 0건으로 적지 말고 측정 불가로 남긴 뒤 안내된 24시간 뒤 다시 봐야 함
- 멈춘 원인과 앱 인벤토리 목록 값은 확인 불가

> 근거: 조회는 이 테넌트에서 직접 읽은 값, 문서는 Microsoft Learn입니다. 비공개 정보는 가렸습니다. 조회 값은 화면에서 직접 읽었습니다.

---

## 전체 기록

### 1. 증상

- 사례 1: M365 Apps 관리 센터. 1·2회차 로딩 정체, 이후 앱 인벤토리는 "프로비전 중, 최대 24시간" 안내와 빈 목록(그림 1)
- 사례 2: Purview DLP 정책 화면. 두 번 "Loading" 정체 후 세 번째에 열림(그림 2, 확인 과정 안)

![앱 인벤토리 프로비전 안내]({{ "/assets/images/2026/10/m11-apps-provisioning.png" | relative_url }})
*그림 1. config.office.com 앱 인벤토리(GUI 경로: config.office.com → 재고)의 프로비전 안내 화면. 10/24 01:15경 다시 열어 촬영했고, 이 시점에도 "서비스를 설정하고 있습니다"와 "이 정보 가져오는 중…"이 그대로여서 목록을 읽을 수 없습니다. 화면에는 인벤토리 데이터를 가져오기 위해 서비스를 설정하는 중이며 장치 수에 따라 전체 인벤토리를 가져오는 데 시간이 걸릴 수 있다는 문구가 있습니다.*

멈춘 화면들은 캡처가 없습니다.

### 2. 원인 및 분석

근거는 화면의 안내 문구뿐입니다. 장치는 Intune Windows 0대, 업데이트 링 0개였고, Azure 포털 직접 주소의 정체(PageLoadTimeout)는 포털 검색창으로 들어가면 정상이었습니다.

<details markdown="1">
<summary>확인 과정 자세히 보기</summary>

#### 나눠 본 순서

1. **로딩이 멈추는 것인가, 안내가 나오는 것인가**
    - 읽은 값: 처음 두 번은 로딩에서 멈춤, 이후에는 프로비전 안내가 나옴
    - 해석: 멈춤과 안내가 같은 원인인지는 화면만으로 알 수 없음
2. **안내 문구가 있는가**
    - 읽은 값: "프로비전 중, 최대 24시간", "서비스를 설정하고 있습니다"
    - 해석: 인벤토리 서비스를 준비 중이라는 뜻으로 읽힘(추정)
3. **측정 대상 장치가 있는가**
    - 읽은 값: 이 테넌트의 Intune Windows 장치는 0, Windows 업데이트 링은 0
    - 해석: 장치가 없는 것과 목록이 비는 것의 관계는 확인하지 못함
4. **다른 화면에서도 같은 일이 있는가**
    - 읽은 값: Purview DLP 정책 화면이 첫 두 번 "Loading"에서 멈췄고 세 번째에 열림
    - 해석: 같은 증상이 시도를 반복하면 풀린 경우가 있음
5. **주소 입력 방식 때문인가**
    - 읽은 값: Azure 포털에서 직접 주소로 연 목록, 만들기 화면이 로딩에서 멈추고 PageLoadTimeout 오류가 한 번 났음. 포털 검색창으로 들어가면 정상
    - 해석: 이 경우는 진입 방식 문제였음

#### 해 본 것과 결과

1. M365 Apps 관리 센터를 열었습니다(1회차). 로딩에서 멈춰 값을 읽지 못했습니다.
2. 같은 화면을 다시 열었습니다(2회차). 역시 로딩에서 멈췄습니다.
3. 앱 인벤토리(config.office.com > 재고)를 다시 열자 "프로비전 중, 최대 24시간" 안내가 나오고 목록은 비어 있었습니다. 값이 아니라 서비스 준비 상태를 읽은 셈입니다.
4. 10/24 01:15경 다시 열어 촬영했는데 같은 안내가 그대로였고, 이 시점에도 목록을 읽지 못했습니다.

DLP 화면은 도구 문제로 보고, 시도 횟수를 기록한 뒤 값은 열린 화면에서 읽었습니다.

![세 번째 시도에서 열린 Purview DLP 정책 화면]({{ "/assets/images/2026/10/m10-1-dlp-policies.png" | relative_url }})
*그림 2. Microsoft Purview > 데이터 손실 방지 > 정책. 앞의 두 번은 "Loading"에서 멈췄고 세 번째에 이 목록(3개 항목)이 열렸습니다. 같은 화면이 시도에 따라 열리기도 하고 멈추기도 한다는 비교용입니다.*

</details>

### 3. 결론

`인벤토리 서비스 준비 중(추정) → 로딩 정체, 프로비전 안내 → 목록 비어 있음`

원인은 확인 불가이고 아무것도 바꾸지 않았습니다. 빈 목록은 "아직 가져오지 못했다"일 수 있어 **측정 불가**로 적었습니다.

<details markdown="1">
<summary>확인 불가 항목 펼쳐 보기 (2건)</summary>

- **M365 Apps 관리 센터 앱 목록**
    - 시도 방법: 화면을 열어 목록 읽기(로딩 2회, 앱 인벤토리 재방문 2회)
    - 막힌 이유: 로딩에서 멈추고, 이후 프로비전 안내만 표시되어 목록이 비어 있음
    - 다음 방법: 안내된 시간(최대 24시간)이 지난 뒤 재조회
- **로딩이 멈춘 원인**
    - 시도 방법: 같은 화면 반복 열기
    - 막힌 이유: 화면에서 멈추는 이유를 알 수 없음
    - 다음 방법: 시간을 두고 다시 열어 같은 증상인지 비교

</details>

### 4. 권고방안

1. 조치: 열 때마다 횟수와 시각을 남기고, 안내된 시간(최대 24시간)이 지난 뒤 다시 봅니다. 직접 주소로 연 화면이 멈추면 포털 검색창이나 메뉴로 들어갑니다.
2. 조치 후 확인: 목록이 실제로 표시되면 해결입니다. 프로비전 안내나 PageLoadTimeout이 남으면 아직 측정 불가입니다.
3. 하지 말아야 할 것: 멈춘 화면을 "0건", "문제 없음"으로 적는 것
