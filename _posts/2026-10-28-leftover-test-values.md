## 요약

| 항목 | 내용 |
|---|---|
| 증상 | 여러 설정을 한꺼번에 조회했더니, 일부 값이 앞서 **변경 시험에서 일부러 바꿔 둔 값**과 정확히 같았음 |
| 먼저 나눈 것 | 원래 설정이 그 값이었는가, 시험이 끝났는데 되돌리지 못한 것인가 |
| 원인 | 변경 시험이 중간에 멈추거나 되돌리기(원복) 단계가 실패해 시험용 값이 Sandbox에 남음 |
| 대처 | 시험용 값 목록과 조회값을 대조 → 일치하면 "잔여 값 가능"으로 표시 → 원래 값을 아는 항목은 그 값으로, 모르면 **확인 불가** → 원복 후 재측정 |
| 결과 | 일치한 항목은 결론을 보류하거나 원래 값 기준으로 쓰고, 재측정 뒤 확정 |

## 풀버전 (전체 과정)

### 1. 상황

설정을 읽기만 하는 스크립트로 여러 항목을 측정했다. 그런데 몇 항목의 값이 우리가 알던 평소 값이 아니었다.

| 설정 | 조회값 | 이상한 점 |
|---|---|---|
| 그룹 이름에 쓰지 못하게 막는 단어 | 시험 때 넣어 둔 낯선 단어 한 개 | 평소에는 비어 있었음 |
| 게스트 초대 범위 | 특정 관리자 역할만 초대 가능 | 평소 값(모든 사용자 초대 가능)과 다름 |
| 통합 감사 로그 수집 | 켜짐(True) | 평소 꺼짐(False)이던 값과 다름 |

세 값 모두 **직전에 돌린 변경 시험이 목표로 삼은 값**과 같았다. 우연이라 보기 어려웠다.

### 2. 어떻게 구분했나

1. **시험용 값 목록을 따로 둔다.** 변경 시험은 "무엇을 어떤 값으로 바꾸는가"를 파일로 남긴다. 조회값이 그 목록과 일치하는지 대조했다. — **조회**
2. **이전 측정 기록과 비교한다.** 같은 Sandbox를 몇 시간 전에 측정한 값이 있으면 그것과 비교한다. 바뀌었다면 그 사이에 누가 바꾼 것이다.
3. **시험 계획서의 "현재 값" 칸을 본다.** 시험 시작 전에 "이미 목표 값과 같음"으로 적혀 있으면, 이전 시험에서 이미 남은 값이다.
4. **원래 값 기록이 없는 항목**은 원래 값을 알 수 없다. 이때는 추측하지 않고 **확인 불가**로 적는다(시도: 이전 측정 기록·시험 계획서 대조, 사유: 원래 값을 적은 기록이 없음).

### 3. 판단 원칙

| 경우 | 결론 표기 |
|---|---|
| 원래 값을 아는 항목(이전 측정 기록 있음) | 원래 값으로 결론을 쓰고, 비고에 "시험 값 잔여 가능 · 원복 후 재측정" |
| 원래 값을 모르는 항목 | **확인 불가** + 대조한 기록과 이유 |
| 조회값이 시험용 값과 달랐던 항목 | 평소대로 결론 |

### 4. 해결: 되돌리고 다시 재기

1. 변경 시험 도구의 원복 기능으로 **남은 변경만 골라 되돌린다.** 화면(GUI)에서 직접 되돌려도 된다.
2. 되돌린 값을 **다시 조회**해서 평소 값으로 돌아왔는지 확인한다.
3. 그 다음에 측정을 다시 하고, 앞의 "잔여 가능" 표시를 지운다.

> 주의: 되돌릴 때는 **시험 때 바꾼 항목만** 되돌린다. 원래 값을 모르는 항목은 임의로 추측한 값을 넣지 않는다.

### 5. 예방

- 변경 시험은 항목마다 **바꾸기 전 값을 먼저 기록**한 뒤 바꾼다.
- 시험이 끝나면 기록한 값으로 되돌렸는지 확인하는 단계를 마지막에 둔다.
- 측정과 변경 시험을 **같은 날 같은 Sandbox에서 연달아** 하지 않는다. 불가피하면 측정 전에 원복 확인부터 한다.
