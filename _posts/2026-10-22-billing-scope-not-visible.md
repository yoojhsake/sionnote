Azure 구독의 청구 계정 유형과 청구 역할을 확인하려고 비용 관리 + 청구를 열었더니 청구 범위 목록이 비어 있었습니다. 권한을 올려서 뚫지 않고, 어디까지 읽었고 무엇이 남았는지를 기록했습니다.

> 근거 표기: **조회** = 화면·PowerShell에서 직접 읽음 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못함(시도 방법·막힌 이유·다음 방법 병기). 테넌트 ID·구독 ID·계정은 게시하지 않았습니다.

## 요약

| 구분 | 내용 |
|---|---|
| 증상 | 비용 관리 + 청구의 청구 범위 목록이 "입력한 필터와 일치하는 항목이 없습니다". 접근 가능한 청구 범위 0건, 청구 프로필 없음, 청구 계정 1개(유형 칸이 비어 있음) |
| 원인 | 확인 불가. 후보는 두 가지: ① 청구 범위에 접근할 권한이 없음, ② 개발자 프로그램 구독이라 EA/MCA 청구 계정 범위가 보이지 않는 구조(추정) |
| 대처 | 청구 역할을 부여받는 것은 보안 변경이라 하지 않음. 청구 담당자에게 확인하는 것으로 남김 |
| 결과 | 청구 계정 유형·내 청구 역할·결제 수단 필요 여부는 **확인 불가**, "추가 구독을 만들 수 있는가"는 판단 불가. 측정 판독은 측정 불가 |

---

## 전체 기록

### 1. 증상

- **GUI 경로**: Azure 포털 > 비용 관리 + 청구 > 청구 범위
- **조회**: 청구 범위 목록이 "입력한 필터와 일치하는 항목이 없습니다"로 비어 있습니다.
- **조회 값**: 접근 가능한 청구 범위 0건, 청구 프로필 없음, 청구 계정 1개(유형 칸이 비어 있음).
- 같은 조회를 사전 환경 점검(10/19)에서 한 번, 운영 설정 실측(10/22)과 10/23에 다시 했고 모두 0건이었습니다.

![청구 범위 목록이 비어 있는 Azure 비용 관리 + 청구 화면]({{ "/assets/images/2026/10/billing-scopes-empty.png" | relative_url }})
*그림 1. 비용 관리 + 청구 > 청구 범위. 표 머리글(청구 범위, 범위 유형, 청구 계정, 계정 유형, 내 역할, 상태) 아래가 비어 "입력한 필터와 일치하는 항목이 없습니다"만 보인다. 계정과 디렉터리 식별 표시는 가렸다.*

### 2. 먼저 확인할 것(나눠 보는 순서)

청구 범위가 비어 있는 이유를 아래 순서로 나눠 보았습니다.

| 순서 | 확인 | 읽은 값(조회) | 해석 |
|---|---|---|---|
| 1 | 구독이 어떤 유형인가 | QuotaId = PayAsYouGo_2014-09-01(종량제), 구독 1개, 상태 Enabled | 개발자 프로그램이 만든 종량제 구독 |
| 2 | 구독에서 내 역할은 무엇인가 | Owner(구독 범위, 영구 활성). Owner가 하나 더 있고 서비스 사용자임 | 구독 Owner인데도 청구 범위는 0건 |
| 3 | 청구 범위·프로필·계정이 보이는가 | 범위 0건, 프로필 없음, 계정 1개(유형 비어 있음) | 계정은 있으나 유형·역할이 화면에 나오지 않음 |
| 4 | 지출 한도 | Off(문서에도 종량제 구독에는 지출 한도 기능이 없다고 있음) | 청구 범위와는 별개의 값 |

여기서 원인을 둘로 좁혔습니다. ① 청구 범위에 접근할 권한이 없다, ② 개발자 프로그램 구독은 EA/MCA 청구 계정 범위가 보이지 않는 구조로 보인다. ②는 **추정**이며 구조 원인은 확인하지 못했습니다.

### 3. 시도와 결과

| 시도 | 결과 | 판단 |
|---|---|---|
| 비용 관리 + 청구에서 청구 범위 목록 열기 | 0건("입력한 필터와 일치하는 항목이 없습니다") | 화면에서 더 읽을 값이 없음 |
| 같은 조회를 다른 날 반복 | 여전히 0건 | 결과가 같음 |
| 청구 계정 유형·내 청구 역할 읽기 | 읽지 못함 | **확인 불가** |
| 결제 수단 필요 여부 읽기 | 읽지 못함 | **확인 불가** |
| 추가 Azure 구독 생성 가능 여부 판단 | 근거가 되는 값을 읽지 못함 | **판단 불가**로 남김 |

### 4. 대처 · 원복

- 청구 범위에 접근하려면 역할을 부여받아야 하는데, 이는 **보안 변경**이라 하지 않았습니다.
- 바꾼 설정이 없으므로 원복할 것이 없습니다.
- 가이드의 안내대로 추가 구독을 만들 수 없으면 내부에 알려야 하므로, 확인 사항으로 올렸습니다.

| 확인 불가 항목 | 시도 방법 | 막힌 이유 | 다음 방법 |
|---|---|---|---|
| 청구 계정 유형 | 청구 범위·청구 계정 조회 | 범위 0건, 계정 유형 칸이 비어 있음 | 청구 담당자에게 확인 |
| 내 청구 역할 | 청구 범위 조회 | 청구 범위에 접근할 권한이 없고, 역할을 부여받는 것은 보안 변경이라 하지 않음 | 청구 담당자에게 확인 |
| 결제 수단 필요 여부 | 청구 범위 조회 | 위와 같음 | 청구 담당자에게 확인 |
| 추가 구독 생성 가능 여부 | 위 값들로 판단 | 근거 값을 읽지 못함 | 위 확인 뒤 판단 |
| EA/MCA 청구 범위 역할(구조 원인) | 청구 범위 목록 조회 | 개발자 프로그램 구독은 EA/MCA 범위가 보이지 않는 구조로 보이나 원인은 확인하지 못함 | EA/MCA 계정이 있는 운영 테넌트에서 청구 범위의 액세스 제어 확인 |

### 5. 운영에서는 이렇게 판단한다

- 청구 범위가 0건이면 "청구 담당이 없다"가 아니라 **내 계정에서는 값이 보이지 않는다**는 뜻일 수 있습니다. "0건"을 "문제 없음"으로 적지 않고 측정 불가로 적습니다.
- 구독 Owner라고 해서 청구 범위까지 읽을 수 있다고 가정하지 않습니다. 이 구독에서는 Owner인데도 청구 범위가 0건이었습니다.
- 비용이 나갈 수 있는 구독(지출 한도 Off)에서는 청구 담당과 청구 역할을 먼저 알아 두는 것이 운영 인수 확인 사항입니다.
- 청구 역할을 직접 부여받아 뚫는 것은 측정이 아니라 권한 변경입니다. 담당자에게 확인하는 경로를 먼저 씁니다.

### 6. 근거 자료

| 구분 | 내용 | 출처 |
|---|---|---|
| 조회 | 청구 범위 0건, 청구 프로필 없음, 청구 계정 1개(유형 비어 있음) | 위 1절 |
| 조회 | 구독 유형 PayAsYouGo_2014-09-01, 지출 한도 Off, 구독 Owner | 위 2절 |
| 문서 | 종량제 구독에는 지출 한도 기능이 없음 | [Spending limit](https://learn.microsoft.com/azure/cost-management-billing/manage/spending-limit) |
| 확인 불가 | 청구 계정 유형·청구 역할·결제 수단 필요 여부 | 위 4절 표 |
