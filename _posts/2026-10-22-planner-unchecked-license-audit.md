시험 사용자 1의 Planner를 다시 켜 87개로 원복해 뒀는데, 같은 날 다시 보니 또 꺼져 있었습니다(앱 86개). 감사 로그에 그 시각 Change user license 기록이 0건이라 "사람이 다시 껐다"는 가설은 기각했지만, 원인은 확인 불가로 남았습니다.

## 요약

- 다시 켜고 저장해 87개로 되돌렸지만 꺼진 이유는 설명되지 않음
- 같은 현상이 보이면 감사 로그부터 보고 원복 뒤에도 시간을 두고 다시 읽으면 됨
- 시스템 주체의 라이선스 변경과 Planner 해제의 관계는 확인 불가

> 근거: 조회는 이 테넌트에서 직접 읽은 값, 문서는 Microsoft Learn입니다. 비공개 정보는 가렸습니다. 시험 사용자는 "시험 사용자 1"처럼 적었습니다.

---

## 전체 기록

### 1. 증상

- M365 관리 센터 > 활성 사용자 > 시험 사용자 1 > 라이선스 및 앱에서 2026-10-22 09:25 Planner를 끄고(87→86) 다시 켬
- 10:3x와 10/23에 다시 보니 **꺼진 상태**(86개)
- 10:3x는 10시 30분대 어느 시점이며 정확한 시각은 기록하지 않았고, 21:5x는 21시 50분대입니다.

![사용자 라이선스 앱 목록. Microsoft Planner 체크가 해제되어 있음]({{ "/assets/images/2026/10/d1-planner-off.png" | relative_url }})
*그림 1. Planner 체크 해제 상태 (빨간 상자, 사용자 이름은 가림). 10/23 21:5x에 같은 화면을 선명하게 다시 캡처한 것입니다. 앱 개수 86은 이 캡처 밖에서 읽은 값입니다.*

### 2. 원인 및 분석

Entra 감사 로그 `Change user license`(7일)의 시각, 시작한 주체, 수정된 속성을 봤습니다(조회).

- 10/22 10:3x: 0건(사람이든 시스템이든 기록 없음)
- 10/23 16:54:49(5건), 16:57:30(1건): 주체 CloudLicensingSystem, 대상 관리자 계정, 수정된 속성 비어 있음

<details markdown="1">
<summary>확인 과정 자세히 보기 (그림 2장)</summary>

#### 확인한 순서

1. 누가, 언제 라이선스를 바꿨는가 → Entra 감사 로그의 활동 "Change user license"
2. 사람이 한 변경인가, 시스템이 한 변경인가 → 항목의 "시작한 주체"
3. 그 변경이 서비스 플랜(Planner)을 껐다는 직접 증거가 있는가 → 항목의 수정된 속성

#### 시도와 결과

오전에는 활동 필터의 적용 버튼이 켜지지 않았습니다(권고방안 3). 드롭다운에서 활동을 골라 다시 적용했고, 기간을 7일로 놓고 활동을 "Change user license"로 거른 결과는 이렇습니다(조회).

- 10/22 9:25:11, 5건: 서비스 플랜 끄기와 켜기 실습
- 10/22 9:31:34, 9:34:48, 각 1건: 다른 시험 사용자에 대한 그룹 기반 라이선스 할당(관련 글 [직접 라이선스와 그룹 라이선스가 겹침]({{ "/m365/troubleshooting/direct-and-group-license-overlap/" | relative_url }})의 첫 실습 9:29~9:33과 시각이 가깝습니다)
    - 시작한 주체가 사람이 아니라 애플리케이션(CloudLicensingSystem)
- 10/22 10:3x, 0건: 기록 없음
- 10/23 10:07:48, 10:12:17, 각 1건: 10/23 시험
- 10/23 16:54:49, 5건: 시작한 주체가 애플리케이션(CloudLicensingSystem), 대상은 관리자 계정
    - 수정된 속성 칸은 비어 있음
    - 이 시각에 사람이 한 라이선스 조작은 기억에도 기록에도 없음
- 10/23 16:57:30, 1건: 위와 같은 형태(주체 CloudLicensingSystem)
- 10/23 21:30:09, 21:35:56, 각 1건: 동적 그룹 시험에서 그룹 가입과 제거에 따른 그룹 라이선스 반영, 회수

![Change user license 감사 로그 목록. 10/22 9:25 5건, 9:31, 9:34, 10/23 10건]({{ "/assets/images/2026/10/m01-audit-license.png" | relative_url }})
*그림 2. GUI 경로: Entra 관리 센터 > 모니터링 및 상태 > 감사 로그 > 날짜 범위 "지난 7일", 활동 "Change user license"로 거른 결과(10/23 저녁에 다시 연 화면, 표시 시각은 KST). 10/22 9:25:11에 5건, 9:31:34와 9:34:48, 10/23 10:07:48과 10:12:17, 16:54:49에 5건, 16:57:30, 21:30:09, 21:35:56이 보이고 10/22 10:3x에는 항목이 없습니다.*

10/23 16:54~16:57의 6건 중 첫 건을 열어 보니, 시작한 주체는 사람이 아니라 애플리케이션 CloudLicensingSystem이었고 대상은 관리자 계정, 수정된 속성은 비어 있었습니다.

### 3. 결론

`10:3x 기록 0건 → "사람이 껐다" 기각 → 원인 확인 불가`

시스템 주체 변경이 Planner를 껐다는 직접 증거는 없습니다. 다시 켜고 저장해 87로 되돌렸습니다(그림 3, 확인 과정 안).

<details markdown="1">
<summary>확인 불가 항목 펼쳐 보기 (2건)</summary>

- **10/23 16:54~16:57 시스템 변경과 Planner 해제의 관계**: 16:54~16:57의 두 시각은 동적 그룹 1회차 측정(부서 입력 16:54:23, 비움 16:56:50 KST)과 각각 약 26초·40초 차이로 맞아, 그룹 가입·제거에 따른 그룹 라이선스 변경일 가능성이 있다고 추정합니다. 다만 항목의 대상이 시험 사용자 2와 같은지는 대조하지 못했고, 10/22 10:3x에 꺼져 보인 현상은 이 항목으로 설명되지 않습니다(**확인 불가**).
    - 시도: 항목의 활동, 대상, 수정된 속성 탭 확인
    - 막힌 이유: 시스템이 남긴 항목이라 원인 필드가 없음
    - 다음 방법: 변경 전후 `assignedPlans` 스냅샷을 정기 수집, 16:54:49 항목의 대상 사용자 ID와 시험 사용자 2의 ID 대조(감사 로그 30일 보존)
- **10/22 10:3x에 왜 꺼져 보였는지**(확인 불가): 조회 화면이 일시적으로 다른 값을 보여 줬을 가능성이 있지만 근거가 없어 추정으로만 둡니다.
    - 시도: 감사 로그 7일 범위 활동 필터
    - 막힌 이유: 해당 시각의 기록이 없어 더 따라갈 단서가 없음
    - 다음 방법: 같은 사용자의 서비스 플랜 상태를 정기적으로 읽어 변화 시각을 남김

</details>

### 4. 권고방안

1. 조치: 서비스 플랜 상태는 감사 로그 상세에 나오지 않으니 변경 전후 `assignedPlans` 스냅샷을 정기 수집합니다.
2. 조치 후 확인: 시간을 두고 다시 읽어 87개가 유지되는지 봅니다.
3. 하지 말아야 할 것: 활동 필터를 입력 칸에 쓰기만 하기(**드롭다운에서 골라야** 적용), 원복을 한 번만 확인하기
