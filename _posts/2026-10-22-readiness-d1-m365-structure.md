수행일은 2026-10-22(목)이고, 프로그램 일정상 D1(M365 구조) 주제입니다. 이 글은 변경 실습을 포함하므로 **무엇을 얼마나 바꿨고 어떻게 되돌렸는지**까지 적었습니다.

> 근거 표기: **조회** = 이 테넌트 화면·PowerShell에서 직접 읽은 값 / **문서** = Microsoft Learn / **미확인** = 확인하지 못한 값. 테넌트 ID·도메인·계정·사용자 이름은 게시하지 않았고, 시험 사용자는 "시험 사용자 1"처럼 적었습니다.

## 1. 목표

1. Tenant와 Subscription이 서로 다른 개념임을 값으로 확인한다.
2. 라이선스(SKU)는 서비스 플랜의 **묶음**이며, 사용자 단위로 플랜 하나만 켜고 끌 수 있음을 직접 해 본다.
3. 그렇게 해도 **라이선스 사용 수는 줄지 않는다**는 점을 숫자로 확인한다.

## 2. 먼저 알아야 할 개념

![라이선스 제품에서 서비스 플랜 묶음, 사용자 단위 켜기·끄기로 이어지는 구조]({{ "/assets/images/2026/10/d1-license-model.png" | relative_url }})
*그림 1. 라이선스 구조와 실습 결과*

| 개념 | 쉬운 설명 | 이 테넌트 값 |
|---|---|---|
| Tenant | 회사의 계정 묶음(신원 경계) | 도메인 1개, 사용자 20, 그룹 9(실습 전) |
| Subscription | Azure 요금·리소스 묶음. 구독은 정확히 하나의 테넌트를 신뢰함 | 구독 1개, 테넌트 소속 확인 |
| SKU | 라이선스 상품 한 종류 | DEVELOPERPACK_V2_E5 1종(구매 25) |
| 서비스 플랜 | SKU 안의 개별 기능(Teams, Planner 등) | 12개 이상 Success, 사용자 화면 앱 목록 87개 |
| 조직 수준 항목 | 사용자별로 못 끄는 항목 | Microsoft Search, eCDN 등은 체크박스가 회색 |

## 3. 절차 (GUI 우선, PowerShell은 읽기 검증)

### 3-1. 10/19 사전 조회

1. 관리 센터 > 청구 > 라이선스 > 구독 탭에서 제품 1개와 "20/25 할당"을 확인했습니다.
2. 제품 이름을 눌러 사용자 목록을 열고, 사용자 한 명을 체크한 뒤 "앱 및 서비스 관리" 패널로 서비스 켜짐/꺼짐을 읽었습니다. 저장하지 않고 닫았습니다.
3. 같은 값을 `subscribedSkus` Graph 조회로 맞췄습니다(서비스 플랜 12개 Success).

### 3-2. 10/22 변경 실습 (09:25, 승인 후 대행)

1. 관리 센터 > 사용자 > 활성 사용자 > **시험 사용자 1** 선택
2. 라이선스 및 앱 탭 > 앱 목록 펼치기 (앱 87개 표시)
3. **Microsoft Planner** 체크 해제 > "변경 내용 저장" → "변경 내용이 저장되었습니다" 메시지
4. 다시 열어 해제 상태가 유지되는지, 앱 개수가 86개로 줄었는지 확인
5. 같은 화면에서 Planner를 다시 체크 > 저장 → 앱 87개로 복귀

![사용자 라이선스 앱 목록. Microsoft Planner 체크가 해제되어 있음]({{ "/assets/images/2026/10/d1-planner-off.png" | relative_url }})
*그림 2. Planner 체크 해제 상태 (빨간 상자, 사용자 이름은 가림)*

|---|---|---|---|

## 5. 문제점과 원인, 해결 방안

### 문제 1 — 가이드의 "제품 상세 > 앱 탭"이 없다

- **원인**: 이 화면의 제품 상세에는 "라이선스", "오류 및 문제" 탭만 있습니다(조회). 화면 버전이 가이드 작성 시점과 다른 것으로 보이나, 원인 자체는 **미확인**입니다.
- **해결 방안**: 사용자를 먼저 선택하고 툴바의 "앱 및 서비스 관리" 또는 사용자 상세의 "라이선스 및 앱" 탭을 쓰는 경로로 바꿨습니다. 가이드 문구 수정 여부는 질문으로 올렸습니다.

### 문제 2 — 한 번 껐다가 켰는데, 나중에 Planner가 다시 꺼져 있었다

- **상황**: 같은 날 10:3x에 확인하니 시험 사용자 1의 Planner가 **꺼진 상태**였습니다.
- **원인**: **미확인**. 사용자가 직접 껐는지, 다른 처리가 영향을 줬는지 구분하지 못했습니다. 감사 로그를 열어 확인하지는 않았습니다.
- **해결 방안(조치)**: 켜고 저장하여 87로 복귀시키고, 이 사실을 기록에 남겼습니다. 운영이라면 같은 현상이 생겼을 때 먼저 **감사 로그에서 누가 언제 바꿨는지**부터 확인하는 것이 순서입니다.
- **교훈**: "원복했다"고 한 번 쓰고 끝내면 틀릴 수 있습니다. 원복 후에도 시간을 두고 다시 읽어 확인해야 합니다.

### 문제 3 — 사용자 5명 생성은 하지 않았다

- 계정 생성은 이번 실습에서 AI가 하지 않는 작업이라 **사용자(본인)가 직접** 하기로 했습니다. 10/19에는 마법사를 열고 아무것도 입력하지 않은 채 취소만 했습니다(취소 확인창 "입력한 모든 정보가 손실됩니다").
- 좌석이 5개뿐이라, 5명에게 직접 라이선스를 주면 25/25가 되어 D2의 그룹 라이선스 실습 좌석이 없어집니다. "4명 할당 + 1명 비움"으로 진행해도 되는지 질문으로 남겼습니다(답 **미확인**).

## 7. 운영에서는 이렇게 판단한다

- 사용자에게 Teams만, 또는 Planner만 막고 싶을 때 SKU를 바꾸지 않고 **플랜 단위로 제어**할 수 있습니다.
- 다만 사용자 단위 수작업은 사람이 늘수록 누락됩니다. 많은 사용자에게 같은 규칙을 적용하려면 그룹 라이선스에서 플랜을 선택하는 방식(D2)이 더 맞습니다.
- 플랜을 껐을 때 사용 수가 줄지 않으므로, **비용 절감 수단으로 오해하면 안 됩니다.**
