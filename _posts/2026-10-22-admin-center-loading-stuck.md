관리 센터 화면이 값을 보여 주지 않고 로딩 상태에서 멈추는 일이 몇 차례 있었습니다. 이 글은 그중 M365 Apps 관리 센터가 목록을 보여 주지 않은 경우를 중심으로, 시도한 방법과 남은 확인 사항을 정리합니다.

> 근거 표기: **조회** = 화면에서 직접 읽음 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못함(시도 방법·막힌 이유·다음 방법 병기). 테넌트 이름·계정은 게시하지 않았습니다.

## 요약

| 구분 | 내용 |
|---|---|
| 증상 | M365 Apps 관리 센터가 두 번 모두 로딩에서 멈춤. 다시 열자 앱 인벤토리(config.office.com > 재고)에 "프로비전 중, 최대 24시간" 안내가 표시되고 목록이 비어 있음 |
| 원인 | 확인 불가. 화면 안내로는 인벤토리 서비스를 설정하는 중이어서 목록이 비어 있는 것으로 보임(추정) |
| 대처 | 설정을 바꾸지 않고 안내된 시간 뒤에 다시 열기. 그동안 이 항목은 측정 불가로 기록 |
| 결과 | 다시 열어 촬영한 시점에도 같은 안내가 그대로였고, 목록 값은 읽지 못함 |

---

## 전체 기록

### 1. 증상

- **GUI 경로**: M365 Apps 관리 센터(config.office.com) > 재고
- **조회**: 처음 두 번은 화면이 로드 중 상태에서 멈췄습니다. 이후 앱 인벤토리를 다시 열자 "프로비전 중, 최대 24시간" 안내가 표시되고 목록이 비어 있었습니다.
- 다시 열어 선명하게 촬영한 시점(10/24 01:15경)에도 "서비스를 설정하고 있습니다"와 "이 정보 가져오는 중…"이 그대로여서 목록을 읽을 수 없었습니다.

![앱 인벤토리 프로비전 안내]({{ "/assets/images/2026/10/m11-apps-provisioning.png" | relative_url }})
*그림 1. config.office.com 앱 인벤토리(GUI 경로: config.office.com → 재고)의 프로비전 안내 화면. 10/24 01:15경 다시 열어 촬영했고, 이 시점에도 "서비스를 설정하고 있습니다"와 "이 정보 가져오는 중…"이 그대로여서 목록을 읽을 수 없다. 화면에는 인벤토리 데이터를 가져오기 위해 서비스를 설정하는 중이며 장치 수에 따라 전체 인벤토리를 가져오는 데 시간이 걸릴 수 있다는 문구가 있다.*

로딩에서 멈춘 첫 두 번의 화면과 Purview DLP 정책 화면의 "Loading" 정체 화면은 남아 있는 캡처가 없어 넣지 못했습니다. 아래는 같은 DLP 정책 화면이 세 번째 시도에서 열린 모습입니다.

![세 번째 시도에서 열린 Purview DLP 정책 화면]({{ "/assets/images/2026/10/m10-1-dlp-policies.png" | relative_url }})
*그림 2. Microsoft Purview > 데이터 손실 방지 > 정책. 앞의 두 번은 "Loading"에서 멈췄고 세 번째에 이 목록(3개 항목)이 열렸다. 같은 화면이 시도에 따라 열리기도 하고 멈추기도 한다는 비교용이다.*

### 2. 먼저 확인할 것(나눠 보는 순서)

| 순서 | 확인 | 읽은 값 | 해석 |
|---|---|---|---|
| 1 | 로딩이 멈추는 것인가, 안내가 나오는 것인가 | 처음 두 번은 로딩에서 멈춤, 이후에는 프로비전 안내가 나옴 | 멈춤과 안내가 같은 원인인지는 화면만으로 알 수 없음 |
| 2 | 안내 문구가 있는가 | "프로비전 중, 최대 24시간", "서비스를 설정하고 있습니다" | 인벤토리 서비스를 준비 중이라는 뜻으로 읽힘(추정) |
| 3 | 측정 대상 장치가 있는가 | 이 테넌트의 Intune Windows 장치는 0, Windows 업데이트 링은 0 | 장치가 없는 것과 목록이 비는 것의 관계는 확인하지 못함 |
| 4 | 다른 화면에서도 같은 일이 있는가 | Purview DLP 정책 화면이 첫 두 번 "Loading"에서 멈췄고 세 번째에 열림 | 같은 증상이 시도를 반복하면 풀린 경우가 있음 |
| 5 | 주소 입력 방식 때문인가 | Azure 포털에서 직접 주소로 연 목록·만들기 화면이 로딩에서 멈추고 PageLoadTimeout 오류가 한 번 났음. 포털 검색창으로 들어가면 정상 | 이 경우는 진입 방식 문제였음 |

### 3. 시도와 결과

| 시도 | 결과 | 판단 |
|---|---|---|
| M365 Apps 관리 센터 열기(1회차) | 로딩에서 멈춤 | 값을 읽지 못함 |
| 같은 화면 열기(2회차) | 로딩에서 멈춤 | 값을 읽지 못함 |
| 앱 인벤토리(config.office.com > 재고) 다시 열기 | "프로비전 중, 최대 24시간" 안내, 목록 비어 있음 | 값이 아니라 서비스 준비 상태를 읽은 것 |
| 10/24 01:15경 다시 열어 촬영 | 같은 안내가 그대로 | 이 시점에도 목록을 읽지 못함 |
| (비교) Purview DLP 정책 화면 | 첫 두 번 "Loading"에서 멈추고 세 번째에 열림 | 도구 문제. 시도 횟수를 기록하고 값은 열린 화면에서 읽음 |

원인은 **확인 불가**입니다. 화면이 로딩 단계에서 멈추는 이유를 화면에서 알 수 없었고, 안내 문구가 멈춤의 이유인지도 확정하지 못했습니다.

### 4. 대처 · 원복

- 바꾼 설정은 없습니다. 안내가 나오는 동안 어떤 버튼도 누르지 않았습니다.
- 이 항목은 **측정 불가**로 적고, 목록 값(앱 인벤토리)은 비워 두었습니다. 0건으로 적지 않았습니다. 비어 있는 것이 "앱이 없다"가 아니라 "아직 가져오지 못했다"일 수 있기 때문입니다.

| 확인 불가 항목 | 시도 방법 | 막힌 이유 | 다음 방법 |
|---|---|---|---|
| M365 Apps 관리 센터 앱 목록 | 화면을 열어 목록 읽기(로딩 2회, 앱 인벤토리 재방문 2회) | 로딩에서 멈추고, 이후 프로비전 안내만 표시되어 목록이 비어 있음 | 안내된 시간(최대 24시간)이 지난 뒤 재조회 |
| 로딩이 멈춘 원인 | 같은 화면 반복 열기 | 화면에서 멈추는 이유를 알 수 없음 | 시간을 두고 다시 열어 같은 증상인지 비교 |

### 5. 운영에서는 이렇게 판단한다

- 화면이 로딩에서 멈추거나 안내만 나오면 **값이 아니라 도구 상태**를 읽은 것입니다. "0건"이나 "문제 없음"으로 적지 않고 측정 불가로 적습니다.
- 같은 화면을 반복해 열 때는 시도 횟수와 시각을 남깁니다. 두 번 멈추고 세 번째에 열린 DLP 화면처럼 횟수가 곧 정체의 기록이 됩니다.
- 안내가 시간을 말하면(최대 24시간) 그 시간이 지난 뒤 한 번 더 확인합니다. 그전에 반복해도 새 정보가 없습니다.
- 직접 주소로 연 화면이 멈추면 포털 검색창이나 메뉴로 들어가 봅니다.
