## 요약

설정을 하나씩 화면으로 보다가 **PowerShell·Graph로 여러 개를 한 번에** 읽기 시작하면 화면에서는 없던 문제가 생깁니다. 이번 주 겪은 것을 "증상 → 먼저 볼 것 → 고친 것" 순서로 모았습니다.

| # | 증상 | 먼저 볼 것 | 고친 것 | 구분 |
|---|---|---|---|---|
| 1 | 실행했더니 **모든 항목이 한꺼번에 실패** | 오류가 항목마다 다른가, 전부 같은가 | 토큰이 만료된 것이므로 다시 연결하고 재실행 | 조회 |
| 2 | 실패 메시지가 섞여 있어 무엇부터 볼지 모름 | 메시지를 **유형별로 묶기** | Forbidden / 세션 미접속 / 값 변환 오류를 따로 처리 | 조회 |
| 3 | `$top=999`를 줬는데 100건만 옴 | 응답에 `@odata.nextLink`가 있는가 | nextLink를 끝까지 따라가 합산(465건, 5페이지) | 조회 |
| 4 | 값이 비어 있을 때 **계산 단계에서 예외** | 대상 값이 null인가 | null을 먼저 검사하고 "해당 없음"으로 출력 | 조회 |
| 5 | 화면 값과 명령 값이 **다르게** 나옴 | 같은 항목인지, 해석 차이인지 | 하나로 단정하지 않고 둘 다 기록 | 조회 |
| 6 | 명령이 "모듈 없음"이거나 환경에 따라 안 됨 | 어느 모듈·어느 PowerShell인지 | 모듈을 명시하거나 REST로 조회, 실행 환경을 바꿈 | 조회·문서 |
| 7 | 결과 표의 이름 열이 서로 섞임 | 한 변수가 두 개체를 가리키는가 | 열을 분리 | 조회 |

## 전체 기록

### 1. 모든 항목이 한꺼번에 실패할 때: 토큰 만료

- **증상**: 한 번에 여러 항목을 읽는 스크립트를 돌렸더니 결과가 전부 "측정 불가"(실패)로 나왔습니다. 항목마다 다른 원인이 아니라 **전부 같은 모양**이었습니다(조회).
- **먼저 볼 것**: 실패가 항목별로 제각각이면 권한·환경 문제, **전부 동시에 같은 모양이면 공통 원인**(로그인·토큰)입니다. 이번에는 공통 원인이었고, 오류 문구는 "Unauthorized" 계열이었습니다.
- **원인**: 토큰 만료로 판단했습니다. 다시 연결한 뒤 같은 스크립트가 정상 동작했기 때문입니다(조회). 토큰이 정확히 언제 만료됐는지는 확인하지 않았습니다.
- **고친 것**: 다시 연결하고 재실행했습니다. 스크립트 안내문에도 "전 항목이 Unauthorized로 나오면 토큰 만료이니 재연결 후 재실행"을 적어 두었습니다.

```powershell
# 다시 연결(필요한 범위를 명시). Cloud Shell 등에서 대화형 동의가 어려우면 환경에 맞는 로그인 방법을 쓴다.
Connect-MgGraph -Scopes "Directory.Read.All","Policy.Read.All"
```

> 위 범위는 예시입니다. 실제로 읽는 항목에 필요한 범위를 확인해 맞춥니다.

- **판단 요령**: 결과가 전부 실패로 나오면 **개별 항목을 들여다보기 전에** 연결 상태부터 확인합니다. 모든 항목의 원인을 따로 찾다가 시간을 쓰는 것을 막아 줍니다.

### 2. 실패 메시지가 섞여 있을 때: 유형별로 묶기

한 번 실행에서 남은 실패 메시지는 크게 세 가지였습니다. **유형이 다르면 처리가 다릅니다.**

| 메시지 | 뜻 | 처리 |
|---|---|---|
| `Response status code does not indicate success: Forbidden (Forbidden)` | **토큰의 Graph 범위나 Entra 역할이 부족**(사람의 권한이 아님) | 필요한 범위·역할을 확인하고 동의, 안 되면 같은 값을 읽는 **화면 경로**로 대체 |
| `Session is not established`(Teams 미접속 등) | 해당 서비스에 **연결하지 않고** 명령을 실행 | 서비스별 연결 명령을 먼저 실행(예: Teams는 `Connect-MicrosoftTeams`) |
| `Cannot convert null to type "System.DateTime"` 등 | **스크립트가 값 형태를 가정**했는데 어긋남 | 값이 없거나 배열일 때의 처리를 추가(아래 4번) |


### 3. `$top=999`를 줬는데 100건만 올 때: 페이징

- **증상**: Graph로 메시지 센터 게시물 목록을 읽을 때 `$top=999`를 줬지만 **한 번에 100건**만 돌아왔습니다(조회).
- **먼저 볼 것**: 응답 맨 위의 `@odata.nextLink`. 값이 있으면 **아직 다음 페이지가 남아 있다**는 뜻입니다. 화면에도 "이 응답에는 @odata.nextLink 속성이 있다"는 안내가 뜹니다.
- **고친 것**: `nextLink`가 없어질 때까지 따라가며 합칩니다. 이번에는 100건씩 5페이지였습니다(조회). 첫 페이지만 보고 "전체 건수"로 적으면 **전체의 일부를 전체로 기록**하게 됩니다.

```powershell
# 메시지 센터 게시물 전체 읽기(읽기 전용). 필요 범위: ServiceMessage.Read.All, 역할: Message Center Reader 이상
$uri = 'https://graph.microsoft.com/v1.0/admin/serviceAnnouncement/messages?$top=100'
$all = @()
while ($uri) {
    $r   = Invoke-MgGraphRequest -Method GET -Uri $uri
    $all += $r.value
    $uri = $r.'@odata.nextLink'     # 마지막 페이지에서는 값이 없어 반복이 끝난다
}
$all.Count
```

![응답에 @odata.nextLink가 포함된 Graph 응답]({{ "/assets/images/2026/10/m23-4-graph-paging-nextlink.png" | relative_url }})
*그림 1. `$top=999`로 요청했지만 응답에 `@odata.nextLink`(`$skip=100`)가 있어 다음 페이지가 남아 있음을 알려 준다. 테넌트 표시와 계정 아이콘은 가렸다.*

- **한 줄 요약**: 목록을 읽을 때는 **개수 제한과 nextLink를 항상 함께** 확인합니다. 문서: [Graph 페이징](https://learn.microsoft.com/graph/paging).

### 4. 값이 비어 있을 때 계산 단계에서 예외가 날 때: null

- **증상**: 화면에서는 "빈 칸"이던 값을 스크립트로 계산(경과 시간 등)하자 예외가 났습니다. 대표적으로 날짜 값이 null인데 뺄셈을 한 경우입니다(조회).
- **사례와 고친 것**

| 상황 | 문제 | 고친 것 |
|---|---|---|
| 온프레미스와 동기화한 적이 없는 테넌트의 "마지막 동기화 시각" | null에서 현재 시각을 빼는 계산이 예외 | null이면 계산하지 않고 **"동기화 미구성(해당 없음)"**으로 출력 |
| 정책의 "수정 시각"이 비어 있는 경우 | 수정 시각 기준 비교가 거짓이 되어 **누락** | 수정 시각이 없으면 **생성 시각**을 대신 사용 |
| 로그인 기록이 한 번도 없는 사용자 | "오래 로그인하지 않음"과 **섞여 집계** | null(기록 없음)을 따로 세어 구분 |

- **판단 요령**: null은 "0"도 "오래됨"도 아닙니다. **"없음"이라는 별도 상태**로 출력하고, 결과 표에서 해당 없음과 정상, 확인 불가를 서로 다른 값으로 적습니다.

```powershell
# null 검사 예: 마지막 동기화 시각이 없으면 경과 시간을 계산하지 않는다
$last = $org.OnPremisesLastSyncDateTime
if ($null -eq $last) { '동기화 미구성(해당 없음)' }
else { [int]((Get-Date) - $last).TotalMinutes }
```

### 5. 화면 값과 명령 값이 다를 때: 하나로 단정하지 않기

- **증상**: 같은 설정인데 화면과 PowerShell 값이 다르게 읽혔습니다. 예를 들어 SharePoint 공유 설정에서 기본 링크 권한이 **화면에서는 "편집"**, `Get-SPOTenant`의 `DefaultLinkPermission`은 **None**이었습니다(조회, 10/26).
- **처리**: 어느 쪽이 맞는지 **추정으로 정하지 않았습니다.** 두 값을 모두 적고 "해석 차이"로 기록했습니다. `None`이 화면의 "편집"에 대응하는지는 문서에 설명이 없어 **확인 불가**이고, 판단에는 같은 설정을 나타내는 다른 속성(익명 링크의 파일·폴더 권한 값)을 썼습니다. 같은 설정을 Graph(`/admin/sharepoint/settings`)로도 읽어 나머지 속성이 화면과 일치하는 것을 확인했습니다(조회).
- **화면 선택 표시가 헷갈릴 때**: 라디오 버튼·슬라이더 표시만으로 어느 값이 선택됐는지 불분명하면 브라우저에서 해당 요소의 선택 상태를 다시 읽어 확인했습니다. 눈으로 읽은 값에 근거가 약하면 그렇게 적습니다.
- **화면과 Graph의 건수가 며칠 사이 조금 다를 때**: 시간이 지난 만큼 항목이 바뀐 것으로 **추정**하고, 추정임을 표시해 두었습니다(확인한 것은 아님).
- **판단 요령**: 불일치는 **오류가 아니라 정보**입니다. 값, 읽은 방법, 읽은 시각을 함께 남기면 나중에 어느 쪽이 갱신됐는지 따질 수 있습니다.

### 6. 명령이 "모듈 없음"이거나 환경에 따라 안 될 때

- **증상**: 문서에 있는 예제 명령이 그대로는 실행되지 않았습니다.
- **원인과 처리**

| 상황 | 원인 | 처리 |
|---|---|---|
| `Get-MgServiceAnnouncementMessage` 같은 Graph 명령이 인식되지 않음 | 해당 명령은 **별도 하위 모듈**(`Microsoft.Graph.Devices.ServiceAnnouncement`)에 있음. `Connect-MgGraph`만으로는 불러지지 않음(문서) | 모듈을 명시해 설치·가져오기, 또는 **REST로 직접 조회**(위 3번 방식) |
| SharePoint·Teams 관리 명령이 Cloud Shell의 Azure 토큰으로는 접속되지 않음 | 그 토큰으로는 해당 서비스 PowerShell에 접속할 수 없었음(`AudienceNotSupported`, 조회) | 내 PC의 **Windows PowerShell 5.1**에서 각 모듈로 직접 로그인해 읽음(10/26, 조회). PowerShell 7에서는 호환 모드가 필요하다는 안내가 있음(문서, 직접 확인 아님) |
| Teams·Exchange 명령 | 각각 별도 연결이 필요 | `Connect-MicrosoftTeams`, `Connect-ExchangeOnline`을 서비스별로 먼저 실행 |

- **판단 요령**: 명령이 안 될 때는 **(1) 모듈, (2) 연결, (3) 권한** 순서로 나눠 봅니다. 모듈이 없으면 오류 메시지가 "인식되지 않는다"이고, 연결이 없으면 "세션이 없다"이며, 권한 문제는 Forbidden으로 나옵니다.

### 7. 결과 표의 이름 열이 섞일 때

- **증상**: 앱 등록의 자격증명 만료를 모아 표로 만들 때, 같은 `DisplayName`을 앱 이름과 자격증명 이름 두 곳에 썼더니 **어느 이름인지 구분되지 않았습니다**(조회).
- **고친 것**: 열을 `App`과 `CredentialName`으로 나눴습니다. 서비스 주체의 자격증명도 만료 대상이므로 따로 집계 대상에 넣었습니다.
- **판단 요령**: 표를 만들기 전에 **한 열이 한 가지 개체만 가리키는지** 확인합니다. 사람이 나중에 읽을 표일수록 열 이름이 의미를 분명히 해야 합니다.

## 정리: 한 번에 읽는 스크립트를 돌릴 때 체크리스트

1. **실행 전**: 연결 상태(토큰 만료 여부), 서비스별 연결, 필요 범위·역할을 확인합니다.
2. **결과를 받으면**: 전부 같은 모양으로 실패했다면 공통 원인(연결·토큰)부터 봅니다.
3. **실패 메시지**는 Forbidden / 연결 없음 / 값 변환 오류로 묶어서 처리합니다.
4. **목록**은 개수 제한과 nextLink를 확인해 일부를 전체로 적지 않습니다.
5. **빈 값(null)**은 별도 상태로 출력하고, 계산 전에 검사합니다.
6. **화면과 명령이 다르면** 둘 다 기록하고 단정하지 않습니다.
7. **읽지 못한 항목**은 비워 두지 말고 "확인 불가 + 시도한 방법 + 사유 + 다음 방법"으로 남깁니다.
