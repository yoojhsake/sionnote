사용자 한 명의 Planner 서비스 플랜을 끄면 라이선스 사용 수도 줄어들까요? 2026-10-22(목) 시험 사용자 1의 Planner를 껐다 켜 보니 앱 수는 87→86→87로 바뀌었지만 SKU 사용 수는 20/25 그대로였습니다.

## 요약

- 서비스 플랜 끄기는 기능 노출만 바꿀 뿐 비용 절감 수단이 아님
- 많은 사용자에게 같은 규칙을 주려면 그룹 라이선스에서 플랜을 고르는 편이 맞음
- 원복 뒤 Planner가 다시 꺼져 보인 원인은 확인 불가라 재조회가 필요함

수행일은 2026-10-22(목)이고, M365 구조를 직접 만져 본 실습 기록입니다. 실제로 설정을 바꿨기 때문에 무엇을 얼마나 바꿨고 어떻게 되돌렸는지까지 적었습니다.

> 근거: 조회는 이 테넌트에서 직접 읽은 값, 문서는 Microsoft Learn입니다. 비공개 정보는 가렸습니다. 시험 사용자는 "시험 사용자 1"처럼 적었습니다.

---

## 전체 기록

### 1. 목표

1. Tenant와 Subscription이 서로 다른 개념임을 값으로 확인합니다.
2. 라이선스(SKU)는 서비스 플랜의 묶음이며, 사용자 단위로 플랜 하나만 켜고 끌 수 있음을 직접 해 봅니다.
3. 그렇게 해도 **라이선스 사용 수는 줄지 않는다**는 점을 숫자로 확인합니다.

### 2. 용어부터 짚고 가기

<picture><source media="(max-width: 640px)" srcset="{{ "/assets/images/2026/10/d1-license-model-m.png" | relative_url }}"><img src="{{ "/assets/images/2026/10/d1-license-model.png" | relative_url }}" alt="라이선스 제품에서 서비스 플랜 묶음, 사용자 단위 켜기·끄기로 이어지는 구조" loading="lazy"></picture>

*그림 1. 라이선스 구조와 실습 결과*

Tenant는 신원 경계이고, 이 테넌트는 실습 전 도메인 1개, 사용자 20, 그룹 9였습니다. Subscription은 Azure 요금과 리소스의 묶음으로 테넌트 하나를 신뢰합니다. 구독 1개의 테넌트 소속도 확인했습니다.

SKU는 라이선스 상품 한 종류입니다. 이 테넌트에는 DEVELOPERPACK_V2_E5 1종(구매 25)이 있습니다. 서비스 플랜은 SKU 안의 개별 기능(Teams, Planner 등)으로, 12개 이상이 Success였고 사용자 화면의 앱 목록은 87개였습니다.

사용자별로 끌 수 없는 조직 수준 항목도 있습니다. Microsoft Search, eCDN 등은 체크박스가 회색이었습니다.

### 3. 결과

#### 전·후 비교

| 항목 | 변경 전 | Planner 끈 직후 | 원복 후 |
|---|---|---|---|
| 앱 개수(화면) | 87 | 86 | 87 |
| Microsoft Planner | 체크됨 | 해제됨 | 체크됨 |
| 저장 메시지 | - | "변경 내용이 저장되었습니다" | 저장됨 |
| 라이선스 사용 수(SKU) | 20 / 25 | 20 / 25 | 20 / 25 |
| 조직 수준 회색 항목 | 끌 수 없음 | 끌 수 없음 | 끌 수 없음 |

라이선스는 사용자에게 "제품 하나"로 할당되므로, 플랜을 끄면 그 안의 기능 노출만 바뀝니다.

#### 검증

다시 열었을 때도 체크 상태가 유지됐고, SKU 사용 수는 읽기 조회로도 20이었습니다. 회색 항목에는 "조직 수준에서 할당됩니다. 사용자 단위로 할당할 수 없습니다" 문구가 있었습니다.

#### 변경 이력

- **언제**: 2026-10-22 09:25
- **무엇을**: 시험 사용자 1의 Microsoft Planner 서비스 플랜 끔 → 켬
- **전 → 후**: 켜짐(87) → 꺼짐(86) → 켜짐(87)
- **왜**: 서비스 플랜 단위 제어가 가능한지, 사용 수가 변하는지 확인
- **근거**: 관리 센터 앱 및 서비스 관리 화면, 문서는 아래 "근거 자료"의 URL
- **검증 결과**: 저장 메시지, 앱 개수 변화, 재조회 시 상태 유지, SKU 사용 20 유지
- **원복 방법**: Planner 체크를 다시 켜고 저장(실행 완료)

### 4. 실무에서 쓸 때

Teams나 Planner만 막을 때는 SKU를 바꾸지 않고 플랜 단위로 제어합니다. 사용자 단위 수작업은 사람이 늘수록 빠뜨리기 쉬워, 여러 명에게는 그룹 라이선스에서 플랜을 고릅니다([Identity 구조 글]({{ "/m365/d2-identity-groups/" | relative_url }})). 원복 뒤에도 시간을 두고 다시 읽어 봅니다. 이번에 실제로 다시 꺼져 있었습니다.

### 5. 절차 (GUI 우선, PowerShell은 읽기 검증)

<details markdown="1">
<summary>절차와 캡처 펼쳐 보기 (그림 2장)</summary>

#### 변경 전 조회

1. 관리 센터 > 청구 > 라이선스 > 구독 탭에서 제품 1개와 "20/25 할당"을 확인했습니다. 값은 [사전작업 글]({{ "/m365/prework/" | relative_url }})에 있습니다.
2. 제품 이름을 눌러 사용자 목록을 열고, 사용자 한 명을 체크한 뒤 "앱 및 서비스 관리" 패널로 서비스 켜짐/꺼짐을 읽었습니다. 저장하지 않고 닫았습니다.
    - 가이드가 안내한 제품 상세의 "앱" 탭은 화면에 없어 이 경로로 대신했습니다(아래 "작업 중 막힌 곳").
3. 같은 값을 `subscribedSkus` Graph 조회로 맞췄습니다(서비스 플랜 12개 Success).

#### 변경 실습 (09:25)

1. 관리 센터 > 사용자 > 활성 사용자 > **시험 사용자 1** 선택
2. 라이선스 및 앱 탭 > 앱 목록 펼치기 (앱 87개 표시)
3. Microsoft Planner 체크 해제 > "변경 내용 저장" → "변경 내용이 저장되었습니다" 메시지
4. 다시 열어 해제 상태가 유지되는지, 앱 개수가 86개로 줄었는지 확인
5. 같은 화면에서 Planner를 다시 체크 > 저장 → 앱 87개로 복귀

![사용자 라이선스 앱 목록. Microsoft Planner 체크가 해제되어 있음]({{ "/assets/images/2026/10/d1-planner-off.png" | relative_url }})
*그림 2. Planner 체크 해제 상태 (빨간 상자, 사용자 이름은 가림). 선명하게 다시 캡처한 화면이며, 이 시점의 앱 개수는 86개였습니다.*

![저장 직후 화면. 변경 내용이 저장되었다는 메시지와 앱(87) 표시]({{ "/assets/images/2026/10/d1-planner-restored.png" | relative_url }})
*그림 3. Planner를 다시 체크하고 저장한 직후 ("변경 내용이 저장되었습니다", 앱 87개, 사용자 이름은 가림)*

원복 뒤 다시 읽었을 때 Planner가 꺼져 있던 일이 두 번 있었습니다(10/22 10:3x, 10/23). 그때마다 켜고 저장해 87개로 되돌렸습니다. 과정은 [트러블슈팅: Planner 체크가 해제돼 있음]({{ "/m365/troubleshooting/planner-unchecked-license-audit/" | relative_url }})에 있습니다.

#### 사용자 5명 생성은 하지 않았다

사용자 계정 생성은 이번 실습 범위에서 뺐습니다. 사전작업 때 마법사를 열고 아무것도 입력하지 않은 채 취소만 했습니다(취소 확인창 "입력한 모든 정보가 손실됩니다").

좌석이 5개뿐이라, 5명에게 직접 라이선스를 주면 25/25가 되어 그룹 라이선스 실습([Identity 구조 글]({{ "/m365/d2-identity-groups/" | relative_url }}))에 쓸 좌석이 없어집니다. "4명 할당 + 1명 비움"으로 진행하는 방안은 확인 사항으로 남겼습니다.

</details>

### 6. 작업 중 막힌 곳

- 가이드의 "제품 상세 > 앱 탭"이 없어, 사용자 선택 후 "앱 및 서비스 관리" 또는 사용자 상세 "라이선스 및 앱" 탭을 썼습니다. ([가이드의 메뉴가 화면에 없음]({{ "/m365/troubleshooting/guide-menu-differs-from-portal/" | relative_url }}))
- 원복한 Planner가 다시 꺼져 있어, 켜고 저장한 뒤 감사 로그로 누가, 언제 바꿨는지 봤습니다. ([Planner 체크가 해제돼 있음]({{ "/m365/troubleshooting/planner-unchecked-license-audit/" | relative_url }}))

### 7. 정리와 남은 일

원복은 끝났고 사용자 5명 생성은 아직 하지 않았습니다. PowerShell 원문은 복구하지 못해 같은 출력 줄이 나오는 형태로 정리했습니다(화면 값은 실제와 같음).

### 8. 확인 불가로 남은 것

<details markdown="1">
<summary>확인 불가 항목 펼쳐 보기 (2건)</summary>

- **10:3x Planner가 꺼져 보였던 원인**
    - 시도: 감사 로그 7일 범위 활동 필터
    - 막힌 이유: 해당 시각 기록 없음. 사람이 껐다는 가설만 기각
    - 다음 방법: 변경 전후 `assignedPlans` 스냅샷 정기 수집
- **가이드의 앱 탭이 없는 이유**
    - 시도: 제품 상세 탭 확인
    - 막힌 이유: 화면 버전 차이로 보일 뿐 근거 없음
    - 다음 방법: 가이드 문구 수정 여부를 확인 사항으로 올림

</details>

### 9. 근거 자료

<details markdown="1">
<summary>근거 자료 펼쳐 보기 (6건)</summary>

- **문서**: 사용자에게 라이선스를 할당하고 앱·서비스를 켜고 끄는 방법
    - 출처: [Assign licenses to users](https://learn.microsoft.com/microsoft-365/admin/manage/assign-licenses-to-users)
- **문서**: 구독은 하나의 테넌트를 신뢰하고, 테넌트는 구독을 여러 개 가질 수 있음
    - 출처: [구독과 디렉터리 연결](https://learn.microsoft.com/entra/fundamentals/how-subscriptions-associated-directory)
- **문서**: 서비스 플랜 이름 참조표
    - 출처: [Service plan reference](https://learn.microsoft.com/entra/identity/users/licensing-service-plan-reference) (이번 글에서 URL 재검증은 안 함)
- **조회**: SKU 구매 25 / 사용 20, 서비스 플랜 12개 Success
    - 출처: 관리 센터 + Graph `subscribedSkus`
- **조회**: 앱 87→86→87, 조직 수준 회색 항목
    - 출처: 관리 센터 사용자 라이선스 화면
- **조회**: 10/22 10:3x에 Change user license 기록 0건(9:25 5건, 9:31·9:34는 시스템의 그룹 기반 할당)
    - 출처: Entra 감사 로그

</details>
