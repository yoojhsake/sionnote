> 근거 표기: **조회** = 실제 포털 화면에서 직접 확인한 값 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못함(시도 방법·사유·다음 방법 병기). 계정·테넌트 식별자는 적지 않았다.

## 요약

| 항목 | 내용 |
|---|---|
| 증상 | 지원 > 서비스 요청 화면의 주소를 직접 입력했더니 왼쪽 메뉴만 나오고 본문이 **빈 화면** |
| 먼저 나눈 것 | 로딩이 덜 끝났는가, 주소가 틀렸는가, 창이 좁아 메뉴가 접혔는가 |
| 원인 | 입력한 주소(`…/#/support/requestlist`)가 실제 화면 주소가 아니었음. 실제는 `…/#/support/requests` |
| 대처 | 왼쪽 메뉴에서 지원 > 지원 서비스 요청 보기를 눌러 주소를 확인 |
| 결과 | **조회**: 서비스 요청 기록 화면 열림, "표시할 티켓이 없습니다"(0건) |

---

## 전체 기록

### 1. 증상

주소 끝의 해시(`#/…`) 부분을 기억나는 대로 입력해 열었더니 상단 바와 왼쪽 아이콘 메뉴만 보이고 본문은 흰 화면이었습니다. 수 초에서 십여 초를 더 기다려도 같았습니다.

### 2. 먼저 확인할 것

| 확인 | 방법 | 결과 |
|---|---|---|
| 로딩 지연인가 | 몇 초 더 기다린 뒤 다시 확인 | 변화 없음 |
| 주소를 다시 열면 되는가 | 같은 주소를 한 번 더 열기 | 변화 없음 |
| 메뉴로 들어가면 열리는가 | 왼쪽 메뉴에서 같은 화면 찾기 | 열림 |

### 3. 시도와 결과

1. 창이 좁아 왼쪽 메뉴가 **아이콘만 있는 접힌 상태**였습니다. 메뉴 단추를 눌러 펼친 뒤 "모두 표시"를 누르자 숨은 항목이 보였습니다. **지원은 처음에는 목록에 없었고** "모두 표시"를 누른 뒤에 나타났습니다(조회).
2. 지원을 펼치면 도움말 및 지원, 지원 서비스 요청 보기, 고객 Lockbox 요청 등이 있었습니다. "지원 서비스 요청 보기"를 누르자 화면이 열렸고, 주소가 `…/#/support/requests`로 바뀌었습니다(조회).
3. 화면 제목은 "서비스 요청 기록"이고, 목록에는 "표시할 티켓이 없습니다"가 나왔습니다(0건).

![서비스 요청 기록 화면에 표시할 티켓이 없다고 나온 화면]({{ "/assets/images/2026/10/support-requests-empty.png" | relative_url }})
*그림 1. 지원 > 서비스 요청 기록. 목록이 비어 "표시할 티켓이 없습니다"가 나온다.*

주소를 조금 바꾼 것만으로 빈 화면이 되는 이유는 문서로 확인하지 못했습니다. 확인 불가(시도: 공식 문서에서 해시 주소 규칙 검색 / 막힌 이유: 해시 경로 규칙을 설명한 문서를 찾지 못함 / 다음 방법: 메뉴 이동으로 얻은 주소만 기록해 사용).

### 4. 대처와 원복

- 설정은 바꾸지 않았습니다. 화면을 열어 읽기만 했습니다.

### 5. 운영에서는 이렇게 판단한다

1. 관리 센터의 해시 주소는 **외워서 입력하지 말고** 메뉴로 들어가 나온 주소를 기록해 씁니다.
2. 본문이 비어 있으면 로딩 지연, 주소 오류, 메뉴 접힘 순서로 나눕니다.
3. 창이 좁으면 메뉴가 접히고 일부 항목은 "모두 표시" 뒤에 나타납니다. 항목이 없다고 단정하기 전에 펼쳐 봅니다.
4. 안내 문서의 주소나 메뉴 이름과 화면이 다르면 실제 화면 기준으로 기록합니다.
