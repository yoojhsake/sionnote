다른 주소에 다녀왔더니 Cloud Shell이 다시 시작되어 `$tk`·`$h` 변수가 사라졌고, 셸이 준비되기 전에 붙여 넣은 명령은 구문 오류(ParserError)가 났습니다. 준비 코드를 다시 실행하고, 셸이 준비된 것을 확인한 뒤 호출 묶음을 한 번에 붙여 넣으면 됩니다.

## 요약

- 다른 주소에 다녀오니 Cloud Shell이 다시 시작되어 `$tk`, `$h` 같은 변수가 사라짐. 셸 준비 전에 붙여 넣은 명령은 두 번 실행되거나 구문 오류
- 탭 이동 때 세션 초기화, 시작 중 입력은 명령이 이어 붙어 해석됨(같은 종류의 오류를 재현해 확인)
- 준비 코드를 다시 실행하고, 셸 준비를 확인한 뒤 호출 묶음을 한 번에 붙여 넣으면 해결
- `(Get-Date) clear` 입력으로 같은 종류의 ParserError 재현. 처음 상황 그대로의 재현은 확인 불가

> 근거 표기: 조회 = 이 테넌트에서 직접 읽은 값, 문서 = Microsoft Learn, 확인 불가 = 시도했지만 확인하지 못한 값(방법·사유 병기). 테넌트 ID, 도메인, 계정, 사용자 이름 등 비공개 정보는 가리거나 게시하지 않았습니다. 토큰도 게시하지 않았습니다.

## 전체 기록

### 1. 증상

Cloud Shell(PowerShell)에서 Graph를 호출하던 중 두 가지가 막혔습니다.

하나는 탭을 이동하면 Cloud Shell이 다시 시작된다는 점이었습니다. 다른 주소로 이동하면 세션이 초기화되어 변수가 사라집니다. 이전에 정의한 `$tk`(토큰), `$h`(헤더), `$B`(Graph 주소)를 다시 정의하지 않고 이어서 호출하면 실패합니다.

다른 하나는 시작 중 입력입니다. 셸이 준비되기 전에 명령을 붙여 넣으면 두 번 실행되거나 구문 오류가 났습니다.

### 2. 원인과 해결

변수가 사라지는 것은 탭을 이동하면 세션이 초기화되기 때문입니다. 준비 코드(토큰, 헤더, 주소 변수)를 다시 실행하면 됩니다. 코드는 [채널 403 글]({{ "/m365/troubleshooting/channel-upload-403-membership-or-scope/" | relative_url }})의 "공통 준비 코드"에 있습니다. 매번 변수를 다시 정의해야 하니 호출 묶음은 한 번에 붙여 넣는 편이 안전합니다.

구문 오류와 이중 실행은 셸 시작 중에 들어온 입력이 이어 붙어 해석되기 때문입니다. 셸이 준비되기 전에는 입력하지 말고, 프롬프트가 나타난 것을 확인한 뒤 입력합니다.

이 대처로 바뀐 설정이나 권한은 없어서 원복할 것도 없습니다.

### 3. 다음에 또 이러면

스크립트가 갑자기 "변수를 찾을 수 없다"는 식으로 실패하면 세션이 초기화되었는지부터 봅니다. 오류 문구가 ParserError라면 호출이나 권한 문제가 아니라 입력이 어떻게 들어갔는지를 의심합니다. 길게 이어서 쓰는 호출은 한 묶음으로 붙여 넣고, 결과 화면에 실행한 명령이 함께 남도록 합니다.

### 4. 확인 과정

<details markdown="1">
<summary>확인 과정 자세히 보기 (그림 1장)</summary>

#### 짚어 본 것

1. 직전에 다른 주소로 이동했는가. 이동했다면 세션이 초기화되어 변수가 없는 것이 정상입니다.
2. 셸 프롬프트가 나타나기 전에 붙여 넣었는가. 준비 전 입력이면 두 번 실행되거나 구문 오류가 날 수 있습니다.
3. 오류 문구가 ParserError인가, 호출 응답 오류(HTTP 코드)인가. ParserError는 명령 모양의 문제이고, HTTP 코드는 호출의 문제입니다.

#### 오류를 다시 만들어 보기

구문 오류는 처음 겪은 순간을 다시 만들 수 없어, 명령이 끝난 뒤 공백만 두고 다른 단어가 붙는 경우를 만들어 봤습니다.

```powershell
(Get-Date) clear   # 명령이 끝난 뒤 공백만 두고 다른 단어가 붙으면 ParserError
```

![셸 시작 중 붙여 넣은 명령의 구문 오류]({{ "/assets/images/2026/10/m14-3-parse-error.png" | relative_url }})
*그림 1. 구문 오류 재현. 처음 겪은 상황(셸이 준비되기 전에 붙여 넣은 명령이 이어 붙음)은 같은 순간을 다시 만들 수 없어, 명령 뒤에 다른 글자가 바로 붙은 `(Get-Date) clear`를 입력해 같은 종류의 오류를 재현했습니다. 빨간 글씨로 ParserError(Unexpected token 'clear' in expression or statement)가 나옵니다. 계정 부분은 가렸습니다.*

결과는 ParserError(Unexpected token 'clear' in expression or statement)였습니다(그림 1, 조회). 한 명령 뒤에 다른 글자가 바로 이어 붙으면 같은 종류의 오류가 난다는 것을 확인했습니다.

셸 시작 중 붙여 넣은 입력이 실제로 어떤 모양으로 이어 붙었는지는 **확인 불가**입니다.

- 시도: 같은 종류의 이어 붙은 명령을 입력해 재현
- 사유: 처음 상황은 같은 순간을 다시 만들 수 없음
- 다음 방법: 같은 증상이 다시 나면 오류 화면 전체를 그대로 저장해 대조
