시험 사용자 1의 Planner를 다시 켜 87개로 원복해 뒀는데, 같은 날 다시 보니 또 꺼져 있었습니다(앱 86개). 감사 로그에 그 시각 Change user license 기록이 0건이라 "사람이 다시 껐다"는 가설은 기각했지만, 원인은 확인 불가로 남았습니다.

## 요약

- 시험 사용자 1의 Planner를 껐다 켜서 87개로 원복했는데, 같은 날 10:3x에 다시 보니 꺼진 상태(앱 86개). 그 뒤에도 같은 현상이 한 번 더 있었음
- 원인은 **확인 불가**. 감사 로그에 10/22 10:3x의 Change user license 기록이 0건이라 "사람이 다시 껐다"는 가설만 기각
- Planner를 켜고 저장해 87로 복귀, 감사 로그로 범위를 좁힘
- 켜짐과 87 복귀는 확인. 원인은 그대로 남음

> 근거 표기: 조회 = 이 테넌트에서 직접 읽은 값, 문서 = Microsoft Learn, 확인 불가 = 시도했지만 확인하지 못한 값(방법과 사유 병기). 테넌트 ID, 도메인, 계정, 사용자 이름 등 비공개 정보는 가리거나 게시하지 않았습니다. 시험 사용자는 "시험 사용자 1"처럼 적었습니다.

---

## 전체 기록

### 1. 증상

M365 관리 센터 > 사용자 > 활성 사용자 > 시험 사용자 1 > 라이선스 및 앱에서 Planner를 끄고(앱 87→86) 다시 켜서 87로 원복했습니다(2026-10-22 09:25). 그런데 같은 날 10:3x에 확인하니 같은 사용자의 Planner가 **꺼진 상태**였습니다. 10/23에 다시 읽었을 때도 같은 사용자가 86개(Planner 해제)였습니다.

![사용자 라이선스 앱 목록. Microsoft Planner 체크가 해제되어 있음]({{ "/assets/images/2026/10/d1-planner-off.png" | relative_url }})
*그림 1. Planner 체크 해제 상태 (빨간 상자, 사용자 이름은 가림). 10/23 21:5x에 같은 화면을 선명하게 다시 캡처한 것입니다. 이 시점의 앱 개수는 86개였습니다.*

### 2. 원인과 해결

#### 원인은 확인 불가, 가설 하나만 기각

10/22 10:3x에 누군가(사람이든 시스템이든) 이 시험 사용자의 라이선스를 바꾼 기록은 **없습니다.** 그래서 "사용자가 다시 껐다"는 가설은 감사 로그로 뒷받침되지 않습니다. 그렇다고 10:3x에 왜 꺼져 보였는지 설명할 수 있는 것도 아닙니다(확인 불가, 아래 '시도와 결과').

10/23 16:54:49의 `Change user license`가 CloudLicensingSystem 주체로 남아 있어서, 라이선스 쪽에 시스템 변경이 있었던 것은 확인했습니다. 다만 그 변경이 Planner를 껐다는 직접 증거는 찾지 못했습니다.

#### 원복

Planner를 다시 켜고 저장해 87로 되돌렸고, 이 사실을 기록에 남겼습니다.

![저장 직후 화면. 변경 내용이 저장되었다는 메시지와 앱(87) 표시]({{ "/assets/images/2026/10/d1-planner-restored.png" | relative_url }})
*그림 2. Planner를 다시 체크하고 저장한 직후 ("변경 내용이 저장되었습니다", 앱 87개, 사용자 이름은 가림)*

### 3. 같은 현상이 또 보이면

먼저 **감사 로그에서 누가 언제 바꿨는지**부터 봅니다. 활동 필터는 값 입력 칸에 쓰는 게 아니라 드롭다운에서 골라야 적용됩니다.

"원복했다"고 한 번 쓰고 끝내면 틀릴 수 있습니다. 원복한 뒤에도 시간을 두고 다시 읽어 확인합니다. 서비스 플랜 단위 상태는 감사 로그 상세에 나오지 않으니, 필요하면 변경 전후 `assignedPlans` 스냅샷을 정기적으로 수집해 둡니다.

### 4. 확인 과정

<details markdown="1">
<summary>확인 과정 자세히 보기 (그림 1장)</summary>

#### 확인한 순서

1. 누가, 언제 라이선스를 바꿨는가 → Entra 감사 로그의 활동 "Change user license"
2. 사람이 한 변경인가, 시스템이 한 변경인가 → 항목의 "시작한 주체"
3. 그 변경이 서비스 플랜(Planner)을 껐다는 직접 증거가 있는가 → 항목의 수정된 속성

#### 시도와 결과

오전에 감사 로그 활동 필터를 걸었는데 적용 버튼이 켜지지 않았습니다. 값 입력 칸에 글자를 쓰는 것만으로는 안 되고, **아래 드롭다운에서 활동을 직접 골라야** 적용이 켜졌습니다.

드롭다운에서 활동을 골라 다시 적용했습니다. 기간을 7일로 놓고 활동을 "Change user license"로 거른 결과는 이렇습니다(조회).

- 10/22 9:25:11, 5건: 서비스 플랜 끄기와 켜기 실습
- 10/22 9:31:34, 9:34:48, 각 1건: 다른 시험 사용자에 대한 그룹 기반 라이선스 할당
    - 시작한 주체가 사람이 아니라 애플리케이션(CloudLicensingSystem)
- 10/22 10:3x, 0건: 기록 없음
- 10/23 10:07:48, 10:12:17, 각 1건: 10/23 시험
- 10/23 16:54:49, 5건: 시작한 주체가 애플리케이션(CloudLicensingSystem), 대상은 관리자 계정
    - 수정된 속성 칸은 비어 있음
    - 이 시각에 사람이 한 라이선스 조작은 기억에도 기록에도 없음
- 10/23 16:57:30, 1건: 위와 같은 형태(주체 CloudLicensingSystem)
- 10/23 21:30:09, 21:35:56, 각 1건: 동적 그룹 시험에서 그룹 가입과 제거에 따른 그룹 라이선스 반영, 회수

![Change user license 감사 로그 목록. 10/22 9:25 5건, 9:31, 9:34, 10/23 2건]({{ "/assets/images/2026/10/m01-audit-license.png" | relative_url }})
*그림 3. GUI 경로: Entra 관리 센터 > 모니터링 및 상태 > 감사 로그 > 날짜 범위 "지난 7일", 활동 "Change user license"로 거른 결과(10/23 저녁에 다시 연 화면, 표시 시각은 KST). 10/22 9:25:11에 5건, 9:31:34와 9:34:48, 10/23 10:07:48과 10:12:17, 16:54:49에 5건, 16:57:30, 21:30:09, 21:35:56이 보이고 10/22 10:3x에는 항목이 없습니다.*

10/23 16:54~16:57의 6건 중 첫 건을 열어 보니, 시작한 주체는 사람이 아니라 애플리케이션 CloudLicensingSystem이었고 대상은 관리자 계정, 수정된 속성은 비어 있었습니다. 그 시각 전후가 Planner 계획을 처음 만든 때라 서비스 프로비저닝과 관련 있을 수 있다고 추정하지만, 근거는 찾지 못했습니다(**확인 불가**).

- 시도: 항목의 활동, 대상, 수정된 속성 탭 확인
- 막힌 이유: 시스템이 남긴 항목이라 원인 필드가 없음
- 다음 방법: 변경 전후 `assignedPlans` 스냅샷을 정기 수집

그렇다면 10:3x에 왜 꺼져 보였는지는 여전히 설명하지 못합니다(확인 불가). 조회 화면이 일시적으로 다른 값을 보여 줬을 가능성이 있지만 근거가 없어 추정으로만 둡니다.

- 시도: 감사 로그 7일 범위 활동 필터
- 막힌 이유: 해당 시각의 기록이 없어 더 따라갈 단서가 없음
- 다음 방법: 같은 사용자의 서비스 플랜 상태를 정기적으로 읽어 변화 시각을 남김

</details>
