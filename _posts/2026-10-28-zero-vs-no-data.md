> 근거 표기: **조회** = 실제 포털 화면에서 직접 확인한 값 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못함(시도 방법·사유·다음 방법 병기). 계정·테넌트 식별자는 가렸다.

## 요약

| 항목 | 내용 |
|---|---|
| 증상 | 여러 화면에서 0 또는 빈 목록이 나왔는데, 어떤 것은 "문제 없음"이고 어떤 것은 "아직 측정이 안 된 것"이었음 |
| 먼저 나눈 것 | 조회가 끝났고 결과가 0인가, 조회할 데이터·평가 대상 자체가 없는가 |
| 기준 | 실제로 조회한 0 = **정상(대상 없음)** / 수집·평가가 없는 0 = **측정 불가** |
| 결과 | 지원 요청 0건은 정상(대상 없음), 정책 준수 0/0과 앱 인벤토리 "가져오는 중"은 측정 불가 |

---

## 풀버전 (전체 과정)

### 1. 같은 0인데 의미가 달랐던 세 화면

| 화면 | 보이는 값 | 의미 | 결론 |
|---|---|---|---|
| 서비스 요청 기록 | "표시할 티켓이 없습니다" | 목록을 조회했고 요청이 0건. 필터도 모두 "모두" | **정상(대상 없음)** |
| Azure Policy 준수 | 전체 리소스 준수 100%, 비준수 0 / **0**, "표시할 할당이 없음" | 평가할 리소스·할당이 0개라 100%가 의미 없음 | **측정 불가** |
| 앱 관리 센터 재고 | "인벤토리 데이터를 가져오기 위해 서비스를 설정하고 있습니다", 각 칸 "이 정보 가져오는 중" | 수집이 아직 시작·완료되지 않음 | **측정 불가** |

### 2. 화면 근거

![서비스 요청 기록 화면에 표시할 티켓이 없다고 나온 화면]({{ "/assets/images/2026/10/support-requests-empty.png" | relative_url }})

*서비스 요청 기록: 작성자·상태 필터가 모두 "모두"인데 티켓이 없다. 실제 0건이다.*

![Azure Policy 준수 화면에서 전체 리소스 준수 100퍼센트이지만 0 나누기 0이고 할당이 없다고 나온 화면]({{ "/assets/images/2026/10/policy-compliance-zero.png" | relative_url }})

*정책 준수: 100%처럼 보이지만 분모가 0이고 "표시할 할당이 없음"이다. 평가가 없는 것이다.*

![앱 관리 센터 재고 화면에서 모든 칸이 가져오는 중으로 나온 화면]({{ "/assets/images/2026/10/app-inventory-no-data.png" | relative_url }})

*재고: 숫자가 아니라 "가져오는 중"이다. 값이 아직 없다.*

### 3. 구분하는 방법

1. **분모를 본다.** "0 / 0"이나 100%처럼 보이는 값은 분모가 0이면 평가 자체가 없다.
2. **목록 위의 필터를 본다.** 필터가 좁혀져 0건일 수 있으니 "모두"로 두고 다시 본다.
3. **안내 문구를 읽는다.** "설정하고 있습니다", "가져오는 중"은 값이 아니라 상태 메시지다.
4. **다른 경로로 한 번 더 확인한다.** 화면이 0이면 같은 값을 명령으로도 읽어 본다. 명령도 0이면 실제 0, 오류나 빈 응답이면 수집 문제를 의심한다.
5. 시간이 지나면 채워지는 항목은 **기다린 뒤 다시** 본다(공식 문서의 안내 시간은 항목마다 다르다).

### 4. 결론 표기 원칙

| 상황 | 표기 |
|---|---|
| 조회 완료, 결과 0 | 정상(대상 없음) — 조회 방법과 조회 시각을 같이 적는다 |
| 평가·수집 없음 | 측정 불가 — 이유(평가 대상 0, 수집 대기)와 다시 재는 조건을 적는다 |
| 이유를 알 수 없음 | 확인 불가 — 시도한 방법과 막힌 이유를 적는다 |

### 5. 주의할 점

- "0이니 안전하다"로 쓰면, 평가가 없는 상태를 잘못 안전하다고 보고하게 된다.
- 반대로 "0이니 측정 불가"로 쓰면, 실제로 문제가 없는 항목을 놓치게 된다.
- 둘 중 무엇인지 모르면 임의로 고르지 말고 **확인 불가**로 두고 판단 기준을 질문한다.
