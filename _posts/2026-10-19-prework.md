실습에서 값을 바꾸기 전, Sandbox 테넌트와 Azure 구독은 지금 어떤 상태일까요(조회 기준일 2026-10-19(월))? 읽기 전용으로 읽어 보니 라이선스는 구매 25 / 사용 20 / 남음 5였고, Azure 구독은 지출 한도가 꺼진 종량제라 "무엇을 만들지 않는다"부터 정했습니다.

## 요약

- 전역 관리자가 영구 활성이고 비상 계정 없이 보안 기본값만 켜져 있음
- 보안 기본값이 장치 코드 로그인을 막으니 스크립트 연결 방식부터 정해야 함
- MFA 로그인 동작과 추가 구독 생성 가능 여부는 확인 불가

> 근거: 조회는 이 테넌트에서 직접 읽은 값, 문서는 Microsoft Learn입니다. 비공개 정보는 가렸습니다. 구독 ID도 게시하지 않았습니다. PowerShell 원문은 복구하지 못해 같은 출력 줄이 나오는 형태로 정리했습니다(출력 값은 실제와 같습니다).

## 전체 기록

### 1. 목표와 범위

실습 뒤 "원래대로 돌아왔는가"를 판단할 전 값을 남기려고, 2026-10-19(월) Sandbox 테넌트와 Azure 구독의 관리자 역할, 로그인 보호, 라이선스, 구독 비용 구조, 가이드 보완 항목을 읽었습니다. 저장·적용 버튼은 누르지 않았고, 예외는 샌드박스에서 허용되는 Planner 계획 생성과 리소스 공급자 등록뿐입니다. 용어는 [클라우드 학습 용어 전집]({{ "/study/cloud-study-glossary/" | relative_url }})을 보세요.

### 3. 판단과 권고

1. 지출 한도 Off 종량제 구독에서는 VM 같은 비용 리소스를 만들지 않고, 리소스 그룹처럼 비용 없는 객체만 만듭니다.
2. 전역 관리자가 영구 활성입니다. 운영 환경이라면 상시 권한은 줄이고 필요할 때만 올려 쓰는 적격 할당을 권합니다([PIM 구성](https://learn.microsoft.com/entra/id-governance/privileged-identity-management/pim-configure)). 비상 계정 문제는 [실측 Identity 글]({{ "/m365/measure-identity/" | relative_url }})에서 다룹니다.
3. 장치 코드 로그인이 막히므로 보안 기본값은 두고 Cloud Shell에서 `Invoke-AzRestMethod`로 Graph REST를 호출합니다(이후 검증은 모두 이 방식).
4. 남은 좌석 5개에 직접 할당으로 사용자를 더 만들면 바로 25/25가 되어, 그룹 라이선스 실습([Identity 구조 글]({{ "/m365/d2-identity-groups/" | relative_url }}))의 사용자 생성 계획(5명)은 확인 사항으로 올렸습니다.
5. MFA는 "등록 가능"만 보고 "MFA 됨"이라고 쓰지 않고, 로그인 프롬프트를 따로 확인합니다.

#### 테넌트, 도메인, 관리자 역할

**GUI 경로**: M365 관리 센터 > 사용자 > 활성 사용자 → Entra 관리 센터 > Entra ID > 개요 → 내 피드의 "역할 정보 보기" > 활성 할당 탭

Cloud Shell에서 읽기 전용으로 Graph `organization`, `domains`를 조회해 화면 값과 맞췄습니다.

```powershell
$o = ((Invoke-AzRestMethod -Uri https://graph.microsoft.com/v1.0/organization).Content | ConvertFrom-Json).value[0]
"$($o.displayName) / $($o.tenantType) / $($o.countryLetterCode)"
((Invoke-AzRestMethod -Uri https://graph.microsoft.com/v1.0/domains).Content | ConvertFrom-Json).value | Select id,isDefault,isVerified
```

조회한 값은 다음과 같습니다.

- 테넌트 종류: AAD, 국가 코드 SG
- 도메인: 1개(기본 도메인, 확인됨, 인증 방식 Managed, 페더레이션 열 비어 있음)
- 개요 카드: 사용자 20, 그룹 9, 애플리케이션 0, 디바이스 1
- 라이선스: Microsoft Entra ID P2
- 내 역할: 전역 관리자, 범위=테넌트, 멤버 자격=직접, 상태=Active, 종료=영구
- PIM 활성 역할: 활성 4건 모두 멤버 자격 직접, 상태 할당됨, 종료 영구. 적격 0건
- 경고 카드: 레거시 MFA/SSPR 정책에서 인증 방법 정책으로 마이그레이션하라는 안내

#### MFA와 보안 기본값

**GUI 경로**: Entra ID > 인증 방법 > 활동 > 사용자 등록 세부 정보 (영문 문서 표기: Entra ID > Authentication methods > Activity. 포털 메뉴 이름은 개편으로 달라질 수 있음) / Entra ID > 개요 > 속성 > 보안 기본값

- 관리자 MFA: "다단계 인증 가능=사용 가능", 기본 방법=Authenticator 앱(푸시). 다른 사용자 대부분은 "불가능"
- 보안 기본값: "조직이 보안 기본값으로 보호됩니다" 표시
- Azure 리소스 액세스 관리 토글: 아니요(권한 상승 안 됨)
- MFA 실제 로그인 동작: **확인 불가**
    - 시도: 로그인 프롬프트 동작 확인
    - 막힌 이유: 본인 계정의 인증 정보를 입력해야 하는 시험이라 하지 않음
    - 다음 방법: 브라우저 InPrivate 창에서 관리자 계정으로 로그인해 프롬프트 확인

인증 방법 메뉴 경로는 처음에 "보호 > 인증 방법 > 모니터링"으로 적었다가 문서 기준 경로(위)로 고쳤습니다. 비슷한 상황은 [트러블슈팅: 가이드의 메뉴가 화면에 없음]({{ "/m365/troubleshooting/guide-menu-differs-from-portal/" | relative_url }})에 정리했습니다.

이 값 때문에 나중에 장치 코드 로그인과 Exchange Online 연결이 막혔습니다([트러블슈팅: AADSTS530035]({{ "/m365/troubleshooting/aadsts530035-device-code/" | relative_url }})). 문서에 따르면 보안 기본값은 레거시 인증을 막고 관리자와 Azure 관리 접근에 MFA를 요구합니다. ([Security defaults](https://learn.microsoft.com/entra/fundamentals/security-defaults))

#### Azure 구독, 지출 한도, 할당량, 역할

**GUI 경로**: portal.azure.com > 구독 > (구독 이름) > 개요 / 액세스 제어(IAM) > 액세스 권한 확인·역할 할당 / 설정 > 사용량 및 할당량(공급자=Compute, 검색 "Korea Central")

```powershell
Get-AzSubscription | % { "$($_.Name) | $($_.State) | QuotaId=$($_.SubscriptionPolicies.QuotaId) | SpendingLimit=$($_.SubscriptionPolicies.SpendingLimit)" }
Get-AzRoleAssignment | Select DisplayName,SignInName,RoleDefinitionName,Scope,ObjectType | Format-Table -AutoSize
Get-AzVMUsage -Location koreacentral | ? { $_.Name.Value -in 'cores','standardBSFamily','standardDSv5Family' } | Select @{n='Name';e={$_.Name.Value}},CurrentValue,Limit
```

- 구독 수 / 상태: 1개, Enabled(활성)
- 구독 유형: QuotaId = PayAsYouGo_2014-09-01 (종량제)
- 지출 한도: Off(해제)
- 부모 관리 그룹: Tenant Root Group, 현재 비용 0.00
- 내 역할: Owner(구독 범위, 영구 활성). Owner가 1건 더 있음
    - 서비스 사용자: 이름 Microsoft-Developer Program-Sample Data Packs, 유형 Application, 생성 2026-08-23(테넌트 생성 시점), 앱 소유 조직은 외부
- vCPU(Korea Central): 전체 0/10, BS 계열 0/10, DSv5 계열 0/0. 다수 계열 0/10, 일부(Confidential 등) 0/0
    - 표기는 "현재 사용/한도" 순서: 0/10 = 사용 0, 한도 10
- 리소스 그룹 수: 1개(Southeast Asia)
- 구독 Owner 서비스 사용자의 용도: 확인 불가
    - 시도: 서비스 사용자 상세 열기 / 막힌 이유: 설명(notes) 항목이 비어 있음 / 다음 방법: 계정 소유자에게 확인

구독 Owner로 등록된 서비스 사용자는 아래 스크립트로 읽었습니다(Azure 역할 할당은 `Get-AzRoleAssignment`, 서비스 사용자 상세는 Graph). 준비 코드 3줄(토큰, `$h`, `$B`)을 먼저 실행했습니다.

```powershell
$tk = [System.Net.NetworkCredential]::new('', (Get-AzAccessToken -ResourceUrl 'https://graph.microsoft.com').Token).Password
$h  = @{ Authorization = "Bearer $tk" }
$B  = 'https://graph.microsoft.com/v1.0'
$sp = Get-AzRoleAssignment -RoleDefinitionName Owner | Where-Object ObjectType -eq 'ServicePrincipal'
foreach ($a in $sp) {
  Invoke-RestMethod -Headers $h -Uri "$B/servicePrincipals/$($a.ObjectId)?`$select=id,displayName,servicePrincipalType,createdDateTime,notes" |
    Format-List id,displayName,servicePrincipalType,createdDateTime,notes
}
```

![구독 Owner 서비스 사용자 상세]({{ "/assets/images/2026/10/m11-3-service-principal.png" | relative_url }})
*그림 4. 구독 Owner로 등록된 서비스 사용자의 상세(위쪽은 실행한 명령). 이름 Microsoft-Developer Program-Sample Data Packs, 유형 Application, 생성 8/23/2026 7:38:51 PM이 나오고 notes(설명)는 비어 있습니다. ID 줄과 계정 부분은 가렸습니다.*

종량제 구독에는 지출 한도 기능이 없어, 리소스를 잘못 만들면 비용이 그대로 청구될 수 있습니다. ([Spending limit](https://learn.microsoft.com/azure/cost-management-billing/manage/spending-limit)) 그래서 가이드의 "비용 발생 금지" 규칙을 따랐습니다. 할당량 때문은 아닙니다. 지역 전체와 BS 계열은 0/10으로 여유가 있고, 한도 0은 DSv5 등 일부 계열뿐입니다.

vCPU 할당량은 지역별, VM 계열별로 따로 걸립니다. ([Regional quota](https://learn.microsoft.com/azure/quotas/regional-quota-requests), [VM quotas](https://learn.microsoft.com/azure/virtual-machines/quotas)) 구독과 테넌트 관계는 [구독이 디렉터리에 연결되는 방식](https://learn.microsoft.com/entra/fundamentals/how-subscriptions-associated-directory)에 있습니다.

#### PowerShell 모듈

Cloud Shell에서 조회해 보니 이랬습니다.

- Az.Accounts: 5.5.3 발견
- MicrosoftTeams: 8.0.0 발견
- Microsoft.Graph: 발견되지 않음(통합 모듈만 없다는 뜻)
    - 문서상 Cloud Shell에는 하위 모듈 8개가 미리 설치됨: Applications, Authentication, Groups, Identity.DirectoryManagement, Identity.Governance, Identity.SignIns, Users.Actions, Users.Functions
    - 이 테넌트의 Cloud Shell에서 하위 모듈을 따로 조회한 값은 확인 불가. 시도: 통합 모듈 이름 조회 / 막힌 이유: 하위 모듈 이름은 조회하지 않음 / 다음 방법: Cloud Shell에서 하위 모듈 이름 조회
- SharePoint Online 관리 모듈: 발견되지 않음

필요한 Graph 하위 모듈이 없을 때는 `Invoke-AzRestMethod`로 Graph REST를 직접 호출하면 같은 조회가 됩니다.

#### 메시지 센터와 Planner 동기화

#### Log Analytics 작업 영역을 만들 수 있는가, 비용 조건은

- **GUI 경로**: 포털 상단 검색창에 "Log Analytics 작업 영역" → 목록 → 만들기 > 기초 탭(입력 없이 닫음) / 구독 > 설정 > 리소스 공급자
- 조회: 작업 영역 0개. 필수 입력은 구독, 리소스 그룹, 이름, 지역(기본 East US).

직접 주소(URL)로 목록이나 만들기 화면을 열면 로딩이 멈추고 PageLoadTimeout 오류가 한 번 났습니다. 포털 검색창으로 들어가면 정상 로딩됩니다.

공급자 등록은 구독 설정 변경이지만 비용이 없어, Microsoft.OperationalInsights와 Microsoft.Insights 두 개를 등록했습니다. 등록 전후 상태는 아래 표와 같고, 원복은 구독 > 리소스 공급자에서 등록 취소(선택, 비용 없음)입니다.

| 리소스 공급자 | 처음 값 | 등록 후 |
|---|---|---|
| Microsoft.Insights | NotRegistered | Registered |
| Microsoft.OperationalInsights | NotRegistered | Registered |
| Microsoft.Management | NotRegistered | 변경 안 함 |
| Microsoft.Consumption | Registered | 변경 안 함 |
| Microsoft.Compute | Registered | 변경 안 함 |
| 예산(Budget) | 0개 | 변경 안 함 |

실행한 스크립트는 읽기 전용입니다. 등록할 때는 `Register-AzResourceProvider -ProviderNamespace microsoft.insights`를 썼습니다.

```powershell
'Microsoft.OperationalInsights','microsoft.insights' | ForEach-Object { Get-AzResourceProvider -ProviderNamespace $_ } |
  Select-Object ProviderNamespace, RegistrationState -Unique | Format-Table -AutoSize
```

![리소스 공급자 등록 확인]({{ "/assets/images/2026/10/m11-2-resource-provider.png" | relative_url }})
*그림 6. Cloud Shell에서 두 리소스 공급자의 등록 상태를 읽은 화면(위쪽은 실행한 명령). Microsoft.OperationalInsights와 microsoft.insights가 모두 Registered입니다. NotRegistered였던 microsoft.insights를 Register-AzResourceProvider로 등록한 직후의 Registering 화면은 다시 만들지 않았고(되돌려 등록 취소하는 변경이 필요해서), 처음 값과 변경 과정은 글 본문 표에 적었습니다. 계정 부분은 가렸습니다.*

Log Analytics 작업 영역 생성 성공 여부는 **확인 불가**입니다.

- 시도: 공급자 등록까지만 함 / 막힌 이유: 작업 영역 생성은 비용이 들 수 있는 항목이라 하지 않음 / 다음 방법: 운영 환경에서 과금 조건을 확인한 뒤 측정

#### 구독 이동 정책과 관리 그룹 계층 보호

- **GUI 경로**: 구독 목록 > 툴바 "정책 관리" / 포털 검색 "관리 그룹"
- 조회: "Microsoft Entra ID에서 나가는 구독", "들어오는 구독" 모두 "어떤 사용자(승격된 전역 관리자 제외)도 허용하지 않음(권장)"이 선택되어 있고 라디오 버튼은 회색(비활성).
    - PowerShell로도 두 값이 True, 예외 주체 0이었습니다.
- 관리 그룹 개요: 그룹 1개 / 구독 1개(Tenant Root Group > 구독). 하단에 "디렉터리 관리자로 등록되었지만 루트 관리 그룹에 액세스할 권한이 없다"는 메시지.

관리 그룹의 계층 보호 설정을 REST로 읽으면 처음에는 HTTP 403(settings/read 권한 없음)이었습니다. 권한 상승(Elevate access)이 필요한 항목이라 [Azure 구조 글]({{ "/m365/d4-azure-structure/" | relative_url }})에서 직접 토글을 켜서 전·후를 확인했고, Elevate를 켠 상태에서 포털 토큰을 갱신하자 값이 읽혔습니다. 최종 값은 기본 관리 그룹 Tenant Root Group, 계층 보호 Off(조회)입니다. 과정은 [트러블슈팅: 관리 그룹 설정 403]({{ "/m365/troubleshooting/mg-settings-403-elevate-access/" | relative_url }})에 정리했습니다.

문서에 따르면 루트 관리 그룹은 기본적으로 아무도 접근 권한이 없고 전역 관리자만 상승할 수 있습니다. ([Management groups 개요](https://learn.microsoft.com/azure/governance/management-groups/overview))

#### 추가 Azure 구독을 만들 수 있는가

조회해 보니 접근 가능한 청구 범위 0건, 청구 프로필 없음, 청구 계정 1개(유형 칸이 비어 있음)였습니다.

- **확인 불가**: 청구 계정 유형, 내 청구 역할, 결제 수단 필요 여부.
    - 시도: 청구 범위를 두 차례 조회했으나 모두 0건이었습니다.
    - 막힌 이유: 청구 범위에 접근할 권한이 없고, 역할을 부여받는 것은 보안 변경이라 하지 않았습니다.
    - 다음 방법: 청구 담당자에게 확인.

"추가 구독을 만들 수 있는가"는 판단 불가로 두고, 가이드 안내대로 확인 사항으로 올렸습니다. [트러블슈팅: 청구 범위·청구 역할이 보이지 않음]({{ "/m365/troubleshooting/billing-scope-not-visible/" | relative_url }})에 정리했습니다.

### 5. 확인 불가로 남은 것

<details markdown="1">
<summary>확인 불가 항목 펼쳐 보기 (7건)</summary>

- **실제 MFA 로그인 프롬프트 동작**
    - 시도: 로그인 프롬프트 동작 확인 / 막힌 이유: 본인 계정의 인증 정보를 입력해야 하는 시험이라 하지 않음 / 다음 방법: 브라우저 InPrivate 창에서 관리자 계정으로 로그인해 프롬프트 확인
- **구독 Owner 서비스 사용자의 용도**
    - 시도: 서비스 사용자 상세 열기 / 막힌 이유: 설명(notes) 항목이 비어 있음 / 다음 방법: 계정 소유자에게 확인
- **Log Analytics 작업 영역 생성 성공 여부**
    - 시도: 공급자 등록까지만 함 / 막힌 이유: 작업 영역 생성은 비용이 들 수 있는 항목이라 하지 않음 / 다음 방법: 운영 환경에서 과금 조건을 확인한 뒤 측정
- **청구 계정 유형, 내 청구 역할, 결제 수단 필요 여부, 추가 구독 생성 가능 여부**
    - 시도: 청구 범위를 두 차례 조회했으나 모두 0건 / 막힌 이유: 청구 범위에 접근할 권한이 없고, 역할을 부여받는 것은 보안 변경이라 하지 않음 / 다음 방법: 청구 담당자에게 확인
- **가이드가 말한 "관리 센터 6종"이 어느 것인지**
    - 시도: 가이드 본문에서 목록 찾기 / 막힌 이유: 본문에 목록이 없음 / 다음 방법: 확인 사항으로 남김
- **서비스 플랜 전체 목록 내용**
    - 시도: 문서 링크만 기재 / 막힌 이유: 이 글을 쓰며 해당 문서를 다시 열어 보지 않음 / 다음 방법: 문서를 열어 이름 대조
- **Cloud Shell의 Graph 하위 모듈 설치 값**
    - 시도: 통합 모듈 이름 조회 / 막힌 이유: 하위 모듈 이름은 조회하지 않음 / 다음 방법: Cloud Shell에서 하위 모듈 이름 조회
