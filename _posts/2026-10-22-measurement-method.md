운영을 인수하기 전에 "지금 이 테넌트가 어떤 상태인가"를 **설정을 바꾸지 않고** 값으로 확인한 과정입니다. 영역별 상세 결과는 아래 글에 나누어 적었고, 이 글은 **측정 방법과 판독 규칙, 전체 분포**를 다룹니다.

> 근거 표기: **조회** = 화면·PowerShell에서 직접 읽음 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못함(시도 방법·막힌 이유·다음 방법 병기). 테넌트 ID·도메인·계정·IP는 게시하지 않았습니다.

## 전체 기록

### 1. 측정 원칙

| 원칙 | 내용 | 이유 |
|---|---|---|
| 읽기 전용 | 정책 편집 화면은 열어 읽기만 하고 **저장·적용·시작·평가판 등록 버튼은 누르지 않음** | 측정이 상태를 바꾸면 측정값을 믿을 수 없고, 운영 책임도 생김 |
| GUI 우선, PowerShell 보강 | 화면 캡처로 근거를 남기고, Cloud Shell의 Graph 호출로 수치를 교차 확인 | 화면과 API가 다르면 이유를 따로 확인하기 위해 |
| 4단계 판독 | 정상 / 주의 / 위험 / 측정 불가 | "못 쟀다"를 "문제 없다"와 구분하기 위해 |
| 근거 3종 표기 | 조회 / 문서 / 확인 불가(시도 방법·막힌 이유·다음 방법 병기) | 확인한 것과 추정한 것을 섞지 않기 위해 |
| 막히면 우회하지 않음 | 로그인 차단, 권한 부족, 라이선스 필요 상태는 원인을 기록하고 멈춤 | 보안 설정을 바꿔 뚫는 것은 측정이 아니라 변경이기 때문 |

측정은 M365 관리 센터·Entra·Azure 포털 세 곳에서 시작했고, Teams·SharePoint·Exchange·Purview 관리 센터도 열어 값을 읽었습니다.

### 2. 측정 흐름

![읽기 전용 측정 흐름: 화면 열기, 값 캡처, 교차 확인, 4단계 판독, 기록]({{ "/assets/images/2026/10/measure-flow.png" | relative_url }})
*그림 1. 설정을 바꾸지 않고 값을 읽어 판독하는 순서*

1. 해당 관리 센터 화면을 열고 현재 값을 읽습니다(저장 버튼은 누르지 않음).
2. 화면을 캡처하고, 공개하지 않을 정보는 가립니다.
3. PowerShell/Graph로 같은 값을 조회해 교차 확인합니다. 가능하지 않으면 그 사유를 적습니다.
4. 판독 4단계 중 하나를 고르고, 근거(문서 URL 또는 조회)를 붙입니다.
5. 변경이 필요해 보이는 항목은 **개선 방안으로만 적고 실행하지 않습니다.**

### 3. 판독 기준

이 글의 판독은 공개 문서의 권고와 운영상 위험을 기준으로 한 **제 판단**이며, 공식 문서가 정한 수치 임계값이 아닙니다.

| 판독 | 뜻 | 예 |
|---|---|---|
| 정상 | 문서의 권고에 맞거나 위험이 없음 | 도메인 1개, 미검증 도메인 0 |
| 주의 | 지금은 괜찮지만 통제가 약하거나 확인이 더 필요함 | 테스트 모드 DLP 정책, 영구 Owner |
| 위험 | 기본값 그대로이거나 통제 장치가 없어 사고 시 영향이 큼 | Anyone 공유 최대 허용, 비상 계정 없음 |
| 측정 불가 | 라이선스·권한·로그인 방식·데이터 부족으로 값을 읽지 못함 | 보고서 데이터 없음, 감사 상태 확인 불가 |
| 해당 없음 | 구조상 대상이 없음 | 클라우드 전용이라 Entra Connect 항목 없음 |

### 4. 예시: Teams 게스트 액세스를 읽는 과정

Teams 관리 센터의 **게스트 액세스** 화면을 열어 값만 읽었습니다(저장·취소 버튼은 누르지 않음).

![Teams 관리 센터 게스트 액세스 화면. Guest access가 Service default: On으로 표시됨]({{ "/assets/images/2026/10/teams-guest-access.png" | relative_url }})
*그림 2. 빨간 상자: Guest access = Service default: On (서비스 기본값 그대로)*

| 읽은 값(조회) | 값 |
|---|---|
| 게스트 액세스 | 서비스 기본값: 켜짐 |
| 게스트 화상회의 | 켜짐 |
| 화면 공유 | Entire screen |
| 외부 참가자 제어 | 꺼짐 |

- **판독: 위험.** 누가 판단해서 정한 값이 아니라 **기본값이 그대로** 적용 중이기 때문입니다. 현재 Guest 사용자는 0명이어서 당장 노출은 없습니다.
- **개선 방안(미실행)**: 게스트 기능의 필요 여부를 정하고, 필요 없으면 끄고, 필요하면 화면 공유를 줄입니다.
- 이 예시가 보여 주는 점: 값이 "켜짐"인 것 자체가 문제가 아니라, **누가 정했는지 모른다**는 것이 위험의 근거입니다.

### 5. 측정 불가 사유 유형

측정 불가는 "시도 → 막힘 → 다른 방법 → 결과"로 기록했습니다. 아래 표는 막힌 유형과 재측정 방법, 확인된 결과입니다.

| 유형 | 예 | 재측정 방법과 결과 |
|---|---|---|
| 라이선스 필요 | SharePoint 데이터 접근 거버넌스 보고서는 SharePoint Advanced Management가 필요(평가판 버튼은 누르지 않음) | 라이선스 확보 후 보고서 생성 |
| 보고서 데이터 없음 | Teams·Office 활성화 사용 현황이 비어 있음 | 활동 발생 후 24~72시간(문서 기준) 뒤 재조회. 나눠 보는 순서는 위 사용 현황 보고서 글에 정리 |
| 로그인 방식 차단 | Cloud Shell의 device-code 로그인이 보안 기본값에 막힘 | 내 PC에서 브라우저 로그인. Exchange는 PowerShell 대신 Exchange 관리 센터(GUI)에서 사서함 20(전부 사용자), Microsoft 365 그룹 9를 읽음. 감사 수집 상태는 내 PC PowerShell로 읽음(Purview 글) |
| 대상 없음 | 클라우드 전용 테넌트라 Entra Connect 항목이 없음 | 하이브리드 환경에서 측정 |
| API/PowerShell 전용 | Restricted SharePoint Search는 포털 화면이 없고 Windows PowerShell 5.1 모듈 전용 | 로컬 Windows PowerShell에서 SPO 관리자로 연결 |
| 화면 오류·정체 | M365 Apps 관리 센터가 두 번 모두 로딩에서 멈춤. 다시 열자 앱 인벤토리에 "프로비전 중, 최대 24시간" 안내가 표시되고 목록이 비어 있음 | 안내된 시간이 지난 뒤 재조회. 과정은 로딩 정체 글에 정리 |
| 열·기능 없음 | 사용자 목록에 마지막 로그인 열이 없고 열 편집 메뉴를 열지 못함 | 열 추가 후 재측정 |
| 접근 범위 없음 | 청구 범위가 0건이라 청구 계정 유형·청구 역할을 읽지 못함 | 청구 담당자에게 확인. 과정은 청구 범위 글에 정리 |

### 6. 판독 결과

![판독 분포: 정상 16, 주의 6, 위험 39, 측정 불가 21]({{ "/assets/images/2026/10/measure-result.png" | relative_url }})
*그림 3. 샌드박스 테넌트 실측 판독 분포 (측정 항목 82개)*

| 판독 | 항목 수 |
|---|---|
| 정상 | 16 |
| 주의 | 6 |
| 위험 | 39 |
| 측정 불가 | 21 |

위 분포(합계 82)는 측정 항목 82개를 판독 결과별로 센 값이며, 다시 세어도 같은 값이었습니다.

**주의**: 영역별 실측 글 4편의 표를 판독별로 더하면 이 분포와 맞지 않습니다. 특히 "주의"는 영역별 표의 합이 6건보다 훨씬 많습니다. 두 표가 같은 항목 목록이 아니기 때문으로 보이나(영역별 표는 설정 단위로 읽은 값을 요약한 표이고 측정 항목 목록은 항목 단위), 항목별 일대일 대조는 하지 않았으므로 정확한 원인은 **확인 불가**입니다.

| 확인 불가 | 시도 방법 | 막힌 이유 | 다음 방법 |
|---|---|---|---|
| 분포 표와 영역별 표의 합계가 다른 원인 | 측정 항목 82개의 영역별 집계와 글 표를 비교 | 글 표의 행과 측정 항목을 이어 주는 대응표가 없음 | 두 표를 같은 기준으로 맞춰 재측정 때 다시 집계 |

이 숫자를 인용할 때는 "측정 항목 82개 기준"으로만 쓰고, 영역별 글의 표는 건수 합산 대상으로 쓰지 마세요.

### 7. 배운 점

- "기본값 그대로"인 설정이 위험 판독의 대부분이었습니다. 외부 공유, 게스트 초대, 앱 동의, 회의 정책이 모두 해당합니다.
- 관리자 계정이 소수여도 **상시 활성 + 비상 계정 없음**이면 위험으로 봅니다.
- 수치는 화면과 API 결과가 같은지 교차 확인합니다. 필터 결과가 의심스러우면(예: 특권 역할 필터) 전체 건수 기준으로 판독합니다.
- 측정 불가가 21건으로 적지 않았습니다. 그중 상당수는 **선행조건(라이선스, 기기, 로그인 방식, 시간)** 문제이므로 운영 인수 전에 해결해 월 단위로 재측정하는 일정이 필요합니다.
