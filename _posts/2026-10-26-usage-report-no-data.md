> 근거 표기: **조회** = 이 테넌트 화면·PowerShell·Graph에서 직접 읽은 값 / **문서** = Microsoft Learn / **확인 불가** = 시도했으나 확인하지 못함(시도 방법·사유·다음 방법 병기). 테넌트·요청 ID는 게시하지 않았고 캡처에서는 가렸다.

## 요약

| 항목 | 내용 |
|---|---|
| 증상 | 관리 센터 사용 현황 화면이 "데이터 없음", Graph 보고서 호출은 HTTP 404 `UnknownTenantId` |
| 먼저 나눈 것 | 권한 오류(403)인가, 데이터 부재(404)인가 |
| 원인 판단 | 권한 오류가 아니라 **보고서 서비스에 이 테넌트의 데이터가 없는 상태**(응답 코드로 판단) |
| 대처 | 표준 채널에 시험 메시지를 남기고, 화면과 Graph를 시각을 달리해 3회 읽음 |
| 결과 | **조회**: 10/26~10/27 동안 계속 비어 있음. 이 보고서에 기대지 않고 다른 화면에서 같은 정보를 읽음 |

## 전체 기록

### 1. 증상

- Microsoft 365 관리 센터 > 보고서 > 사용 현황 화면에 **"There is no data for this report."**가 나왔습니다(조회, 10/26 23:39). 화면 설명에는 "모든 보고 기간에 대한 데이터가 즉시 존재하지 않으며, 보고서는 48시간 이내에 사용할 수 있다"고 적혀 있습니다.
- 같은 내용을 Graph로 읽으면 `GET /reports/getTeamsTeamActivityDetail(period='D7')`가 **HTTP 404**와 함께 `UnknownTenantId`("이 테넌트 ID를 인식하지 못한다")를 돌려줬습니다(조회).

![사용 현황 보고서가 데이터 없음으로 표시된 화면]({{ "/assets/images/2026/10/m23-2-usage-report-no-data.png" | relative_url }})
*그림 1. 관리 센터 사용 현황 화면. 모든 보고서 탭에서 "There is no data for this report."가 나온다. 테넌트 표시는 가렸다.*

![Graph 보고서 호출이 UnknownTenantId 404로 응답]({{ "/assets/images/2026/10/m23-1-teams-report-unknowntenantid.png" | relative_url }})
*그림 2. `getTeamsTeamActivityDetail(period='D7')` 호출 결과. 404이며 오류 코드는 UnknownTenantId다. 응답 속 테넌트 ID와 요청 ID는 가렸다.*

### 2. 먼저 확인할 것: 403인가 404인가

응답 코드부터 읽습니다. 같은 "안 보임"이라도 코드에 따라 가야 할 방향이 다릅니다.

| 응답 | 의미 | 이번 경우 |
|---|---|---|
| 403 Forbidden / accessDenied | 토큰 범위나 역할이 부족. 동의·역할을 확인할 대상 | 아님 |
| 404 `UnknownTenantId` | 요청은 받아들여졌지만 **보고서 서비스가 이 테넌트의 데이터를 갖고 있지 않음** | 해당 |

보고서 읽기 권한(Reports.Read.All)을 따로 동의하지 않은 상태였는데도 응답이 **권한 오류가 아니라 UnknownTenantId**였습니다(조회). 그래서 권한 동의를 늘려 다시 시도하는 쪽이 아니라, 데이터가 쌓이기를 기다리며 같은 방식으로 읽어 보는 쪽으로 정했습니다.

다만 "권한이 충분해서 이 응답이 나온 것"이라고는 말할 수 없습니다. 권한을 추가했을 때 결과가 달라지는지는 **시도하지 않았습니다.**

### 3. 시도와 결과

1. **활동 만들기**: 보고서에 집계될 활동이 있어야 하므로 표준 채널에 시험 메시지 2건을 남겼습니다(10/26 19시대). 새 테넌트는 사용 이력이 거의 없어 보고서가 비어 있을 수 있기 때문입니다.
2. **시각을 달리해 반복**: 같은 Graph 호출을 10/27 10:29와 19:17(KST)에 실행했습니다. 두 번 모두 같은 404 `UnknownTenantId`였습니다(조회). Teams 관리 센터의 팀 사용 현황 보고서도 "데이터를 불러올 수 없음"이었습니다(조회).
3. **판단**: 시각을 달리해 세 번 읽어도 같은 결과였으므로 일시적인 화면 오류는 아니었습니다. 이 글에서는 "비어 있다"는 **관찰 결과만** 기록하고, 비어 있는 이유는 적지 않습니다.

### 4. 대처와 원복

- 이 상황에서 바꾼 설정은 없습니다. 시험 메시지 2건을 남긴 것이 유일한 변경이고, 원복이 필요한 작업이 아닙니다.
- 보고서 값이 꼭 필요한 항목은 이 보고서에 기대지 않고, 같은 정보를 다른 경로(Teams 관리 센터 정책 화면, Entra 로그인 로그 등)로 읽을 수 있는지 먼저 봅니다.

### 5. 운영에서는 이렇게 판단한다

1. **응답 코드를 먼저 읽습니다.** 403이면 범위·역할, 404나 서비스 상태 오류면 데이터·서비스 상태 쪽입니다.
2. **화면과 명령을 같이 봅니다.** 화면도 비어 있고 Graph도 비어 있으면 권한 문제일 가능성이 낮습니다.
3. **시각을 달리해 반복합니다.** 몇 시간 뒤, 하루 뒤에 같은 요청을 보내 "지연"인지 "고정된 상태"인지 나눕니다.
4. **보고서가 비어 있을 때 0건으로 적지 않습니다.** 0건으로 적으면 "활동이 없었다"는 사실처럼 읽히므로, "데이터 없음 응답"이라고 있는 그대로 적습니다.
