## 목표
운영 인수 전에 테넌트의 현재 설정이 어떤 상태인지, **설정을 바꾸지 않고** 값으로 확인한다.

*그림 1. 설정을 바꾸지 않고 값을 읽어 판독하는 순서*

## 원칙
- **읽기 전용**: 정책 편집 화면은 열어서 읽기만 하고 저장·적용은 누르지 않는다.
- **GUI 우선, PowerShell 보강**: 화면 캡처로 근거를 남기고, Cloud Shell의 Graph 호출로 수치를 교차 확인한다.
- **판독은 4단계**: 정상 / 주의 / 위험 / 측정 불가. 기준 경계는 문서의 권고와 내부 기준을 구분해 적는다.
- **측정 불가도 결과**: 못 잰 이유와 재측정 방법을 같이 남긴다.

## 예시: Teams 게스트 액세스
Teams 관리 센터의 **게스트 액세스** 화면을 열어 값만 읽었다(저장·취소 버튼은 누르지 않음).

![Teams 관리 센터 게스트 액세스 화면. Guest access가 Service default: On으로 표시됨]({{ "/assets/images/2026/10/teams-guest-access.png" | relative_url }})
*그림 2. 빨간 상자: Guest access = Service default: On (서비스 기본값 그대로)*

- 읽은 값: 게스트 액세스 서비스 기본값 켜짐, 게스트 화상회의 켜짐, 화면 공유 Entire screen, 외부 참가자 제어 꺼짐
- 판독: **위험** — 누가 정한 값이 아니라 기본값이 그대로 적용되고 있기 때문이다.

## 측정 불가 사유 유형

| 유형 | 예 | 재측정 방법 |
|---|---|---|
| 라이선스 필요 | SharePoint 데이터 접근 거버넌스 보고서는 Advanced Management 필요 | 라이선스 확보 후 보고서 생성 |
| 보고서 데이터 없음 | 사용 현황 보고서가 비어 있음 | 활동 발생 후 약 48시간 뒤 재조회 |
| 로그인 방식 차단 | Cloud Shell의 device-code 로그인이 보안 기본값에 막힘 | 본인 PC에서 브라우저 로그인 |
| 대상 없음 | 클라우드 전용 테넌트라 Entra Connect 항목이 없음 | 하이브리드 환경에서 측정 |
| API 전용 | 일부 기능은 포털 화면 없이 Graph 호출만 가능 | 권한 있는 앱·계정으로 호출 |

## 배운 점
- "기본값 그대로"인 설정이 위험 판독의 대부분이었다. 외부 공유·게스트 초대·앱 동의·회의 정책이 모두 해당한다.
- 관리자 계정이 소수여도 **상시 활성 + 비상 계정 없음**이면 위험으로 본다.
- 수치는 UI와 Graph 결과가 같은지 교차 확인한다. 필터 결과가 의심스러우면(예: 특권 역할 필터) 전체 건수 기준으로 판독한다.
