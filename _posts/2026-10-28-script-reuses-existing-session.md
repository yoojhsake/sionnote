받은 조회 스크립트가 이미 접속된 세션을 그대로 쓰면, 이전에 다른 테넌트로 접속해 둔 창에서는 다른 테넌트의 값이 우리 결과로 기록됩니다. 스크립트는 고치지 않고, 대상 테넌트 ID로 새로 접속해 접속한 테넌트 ID가 같을 때만 실행했습니다.

## 요약

- 받은 조회 스크립트가 "이미 접속된 세션이 있으면 그대로 쓴다". 이전에 다른 테넌트로 접속해 둔 창에서 실행하면 **다른 테넌트의 값**이 우리 결과로 기록될 위험
- 출발점은 접속 코드가 스크립트 안에 있는가, 밖(실행하는 사람)에 있는가. 기존 접속 재사용 분기가 있으면 접속 대상이 실행 창 상태에 따라 달라짐
- 스크립트는 고치지 않음. 실행 앞단에서 대상 테넌트 ID로 새로 접속하고 **접속한 테넌트 ID가 대상과 같을 때만** 실행
- Graph, Azure, Teams, Exchange 묶음에서 접속 테넌트가 대상과 일치함을 기록(조회). SharePoint는 관리 주소로 확인

> 근거 표기: 조회 = 이 테넌트에서 직접 읽은 값, 문서 = Microsoft Learn, 확인 불가 = 시도했지만 확인하지 못한 값(방법과 사유 병기). 테넌트 ID, 도메인, 계정, 사용자 이름 등 비공개 정보는 가리거나 게시하지 않았습니다.

---

## 전체 기록

### 1. 증상(상황)

조회 스크립트 중 일부는 `Get-MgContext`, `Get-AzContext` 같은 명령으로 기존 접속이 있는지 보고, 있으면 다시 접속하지 않습니다. 같은 PC에서 여러 테넌트(예: 다른 사람의 시험 테넌트, 고객 테넌트)에 번갈아 접속하는 환경에서는, 이 동작 때문에 **어느 테넌트의 값인지 모른 채 결과가 저장**될 수 있습니다.

이번 작업에서 실제로 틀린 값이 기록된 일은 없었고, 위험을 미리 막은 사례입니다.

### 2. 원인과 해결

원인은 접속을 스크립트가 직접 하지 않고 "지금 열린 세션"에 맡기는 구조입니다. 해결은 스크립트 밖, 실행 앞단에서 접속과 확인을 하는 것입니다.

1. 스크립트 원본은 수정하지 않았습니다. 받은 그대로 써야 비교하고 재현하기 쉽습니다.
2. 실행 앞단에서 **대상 테넌트 ID를 지정해 새로 접속**했습니다(`-TenantId` 사용).
3. 접속 직후 **접속한 테넌트 ID가 대상과 같은지 비교**하고, 다르면 스크립트를 실행하지 않고 중단하게 했습니다.
4. 서비스마다 확인 방법이 달라 각각 따로 처리했습니다. 상세는 아래 4번에 있습니다.

설정은 바꾸지 않았으니 원복할 것은 없습니다. 실행 기록에는 접속 계정과 테넌트 일치 여부를 함께 남겼고, 계정과 ID는 이 글에 적지 않았습니다.

### 3. 남의 스크립트를 받아 돌릴 때

받은 스크립트는 **접속을 직접 하는지**부터 읽습니다. 여러 테넌트를 오가는 PC라면 실행 전에 항상 대상 테넌트로 새로 접속하고, 접속한 테넌트를 눈과 코드로 한 번 더 확인합니다.

결과 파일에는 대상 테넌트(또는 접속 주소)를 함께 남깁니다. 읽기 전용 스크립트라도 "어느 테넌트의 값인가"가 틀리면 결과 전체를 쓸 수 없습니다.

### 4. 확인 과정

확인한 순서는 이렇습니다.

<details markdown="1">
<summary>확인 과정 자세히 보기</summary>


1. 스크립트가 접속을 직접 하는가: 스크립트 앞부분의 `Connect-*` 호출 유무, 기존 접속 재사용 분기를 봤습니다.
2. 지금 세션이 어느 테넌트인가: `Get-MgContext`의 TenantId, `Get-AzContext`의 Tenant, `Get-CsTenant`의 TenantId를 봤습니다.
3. 결과 파일에 테넌트가 적히는가: 결과 열에 테넌트 정보가 없으면 나중에 구별할 수 없습니다.

서비스별로 직접 실행해 확인한 값(조회)입니다.

| 서비스 | 확인 방법 | 결과(조회) |
|---|---|---|
| Graph | 접속 후 컨텍스트의 TenantId 비교 | 일치 |
| Azure | 컨텍스트의 Tenant ID 비교 | 일치 |
| Teams | `Get-CsTenant`의 TenantId 비교 | 일치 |
| Exchange·Purview | 접속 정보의 TenantID 비교(스크립트가 직접 접속) | 일치 |
| SharePoint | 관리 주소(`<테넌트>-admin`)가 대상인지 확인 | 주소 일치(ID 비교는 하지 않음) |

SharePoint는 테넌트 ID가 아니라 주소로 확인했고, 테넌트 ID 비교는 하지 않았습니다. 주소에 테넌트 이름이 들어 있어 사실상 같은 효과지만 ID 비교와는 다른 확인입니다.

</details>
